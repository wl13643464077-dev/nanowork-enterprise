# 纳米Work行业版

> 进入千行百业，赋能每一个认真创业的老板

面向餐饮等实体门店老板的一体化经营工作台。系统把经营数据、70 位完整岗位数字员工（60 位餐饮员工 + Paihuo 内容生产部 10 位员工）、内容生产、经营工具和任务产出放在同一条可追溯链路中：看见问题、找到匹配岗位、按指引派活、人工核验结果，再回到经营分析持续复盘。

## 当前能力

- 老板驾驶舱：按权限展示营业额、订单、客户漏斗、活动、待办与经营趋势；非管理角色不会看到或聚合企业全量经营数据。
- 70 位完整岗位数字员工：60 位餐饮员工覆盖 8 个专业分部，Paihuo 内容生产部 10 位员工进入内容生产仓；70 位均可单独派活。
- 七面板完整工作台：每位员工均提供“单独派活、能力、工作方式、技能库、提示词、工作配置、岗位档案”；出厂核心能力和岗位 Skill 锁定启用，企业配置只能追加，不能削弱岗位合同。
- 岗位专属派活指引：70 位员工分别展示与职责匹配的问题示例、资料清单、输入提示和交付检查项，不用通用经营问题冒充岗位指引。
- 完整技能库：安全白名单快照保留 409 张历史技能卡，其中餐饮员工 344 张、内容员工 65 张；历史技能以 `legacy_unverified` 待核验状态进入执行，不能冒充当前平台事实。
- 统一文件输入：派活时可从本企业文件中心选择最多 6 个附件；服务端校验租户、用户权限和文件有效性，只把可读取内容作为不可信资料注入。另可附 1 张 PNG、JPEG 或 WebP 内联图片，原图不写入任务快照。
- 内容生产仓：10 位正式员工覆盖趋势、情报、拆解、撰稿、文风、视觉、封面、演绎、分发与复盘。每位员工执行严格的岗位 JSON 输出契约；契约不合格的结果只能驳回或修复，不能采纳。演绎师以完整、安全的 HTML 为主交付，PPT 仅为附加连接器。
- 内容任务闭环：支持手动创作、立即自动执行、每日定时和每周定时；员工与任务类型必须匹配。内容员工单独派活必须审阅采纳，其他内容按风险与规则进入“待审核”或“可使用”；任何路径都不会自动发布，外部人工发布后才能登记渠道、浏览量和线索效果。
- 素材真实引用：一次创作可选择最多 6 份本企业可见素材。服务端注入已持久化正文或明确的文件引用，生成成功后才写入引用关系并增加使用次数；任务快照保留不可变素材快照与哈希，不能用一次点击冒充真实使用。
- 两阶段计费：内容文案、后台任务、PPT、图片、日更包、立即自动与定时自动均先做原子预授权；只有业务产物、审批、资产和引用在同一事务中落库成功后才结算。未交付全额退回，结算异常保留为待对账，页面不会把预授权冒充实扣。
- 自动任务安全：按上海时区计算计划时间，使用原子认领和唯一认领键避免并发重复执行；服务恢复时会把超时运行安全终止并记录失败，不会借恢复流程自动发布。
- 经营工具箱：今日必发、视频混剪、私域日历、竞品盯梢、起号军师、线索雷达、产品图文、口播矩阵。全部免费不消耗积分；已配置 AI 模型时由对应数字员工真实生成，未配置或调用失败时自动回退本地安全模板，结果页如实标注执行模式。
- 经营洞察闭环：统一筛选餐饮员工任务、内容员工单独派活、内容成品与工具运行记录，并可穿透到输入、产出原文、岗位修订、提示词哈希、能力、配置、技能、附件证据、联网证据和审批边界。
- 账号安全：账号采用可恢复的软停用，保留用户 ID、历史内容、任务、审批和运行归属；停用时同步关闭其仍启用的内容自动任务，并保护当前账号、平台超级管理员和企业最后一个老板/管理员。

所有数字员工和工具产出都是待人工核验的经营草案。系统不会自动发布内容、修改价格、采购、排班、处罚员工或代表企业作出外部承诺。

## 本地启动

要求 Node.js 22.12+。

```bash
npm --prefix server ci
npm --prefix web ci
npm run build

# 本地功能验证时可初始化样例数据；生产环境不得启用 SEED_DEMO
NODE_ENV=development SEED_DEMO=true npm start
```

浏览器打开 [http://127.0.0.1:3107](http://127.0.0.1:3107)。新项目固定使用独立默认端口 `3107`，不占用、停止或重启现有项目的 `3007` 服务。

本地初始化账号：

- 老板：`guan / 123456`
- 企业管理员：`admin / 123456`
- 平台超级管理员：由首次初始化时的 `PLATFORM_SUPER_PASSWORD` 或当前独立数据库决定，不在仓库中保存固定密码。

本地自定义配置可先执行 `cp server/.env.example server/.env`。模板默认为 `development`，AI 和飞书凭据均留空。生产环境禁止启用 `SEED_DEMO`；`JWT_SECRET` 必须是至少 32 字节的强随机串，首次初始化的 `PLATFORM_SUPER_PASSWORD` 必须至少 12 位且包含四类字符中的至少三类。

前后端分离开发：

```bash
npm --prefix server run dev
npm --prefix web run dev
```

## 验证

```bash
npm run verify
```

`verify` 依次运行后端测试、前端 TypeScript 检查、多租户隔离扫描与生产构建。验收重点包括：70 位员工完整岗位合同与专属派活指引、七面板工作台、文件权限与附件快照、内容岗位输出契约、人工审核/采纳/发布登记、自动任务调度与恢复、账号软停用、权限隔离和前端生产构建。最终结果以本机当次命令输出为准，不在文档中固化易过期的测试数量。

服务启动后还可对当前运行实例做只读验收：

```bash
NANOWORK_ACCEPT_USERNAME='管理账号' \
NANOWORK_ACCEPT_PASSWORD='对应密码' \
npm run accept:runtime
```

该命令会实际登录并逐个核对 60 位餐饮员工、10 位 Paihuo 内容员工、岗位专属派活指引、内容部门目录、每日/每周自动任务及禁止自动外发边界。

## 数据与安全边界

- 默认数据库：`server/data/nanowork-industry.db`。
- 3107 本地预览数据库：`server/data/nanowork-preview.db`，通过 `NANOWORK_DB` 显式指定。
- `server/.env`、数据库、日志和构建产物均被忽略，不应提交。
- 内容生成、立即自动执行和定时执行都不会自动发布。命中风险或配置为全部审核的结果须审批通过；无风险且规则允许的结果可进入“可使用”，但导入、对外发布和效果登记仍由有权限人员明确操作。
- 内容生产按单员工、单岗位任务执行，不把尚未真实执行的阶段展示成自动十工位流水线。
- 撰稿人 #3、多媒体师 #5、演绎师 #7 的文案/媒体/PPT 连接器是附加入口，不替代其完整岗位能力；演绎师仍以 HTML 为主交付。
- 食品安全、财务、法律、隐私和外部执行事项必须由授权人员复核。

产品映射与验收口径见 [整合规格](docs/纳米Work行业版-整合规格.md)，内容岗位与运行边界见 [内容生产仓](docs/内容生产仓.md)，验收项目见 [验收清单](docs/验收清单.md)，本次实测结果见 [最终验收记录](docs/最终验收记录-2026-07-25.md)，视觉规范见 [DESIGN](docs/DESIGN.md)。
