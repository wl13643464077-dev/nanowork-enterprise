# 纳米Work行业版

> 进入千行百业，赋能每一个认真创业的老板

面向餐饮等实体门店老板的一体化经营工作台。系统把经营数据、72 位完整岗位数字员工（餐饮 61 位：60 位核心员工 + 1 位巡店扩展员工；Paihuo 内容生产部 10 位员工 + 1 位 NanoWork 原生 AI 带货员）、内容生产、经营工具和任务产出放在同一条可追溯链路中：看见问题、找到匹配岗位、用一句目标派活、按风险策略验收结果，再回到经营分析持续复盘。

## 当前能力

- 老板驾驶舱：按权限展示营业额、订单、客户漏斗、活动、待办与经营趋势；非管理角色不会看到或聚合企业全量经营数据。
- 72 位完整岗位数字员工：餐饮 61 位（60 位核心员工覆盖 8 个专业分部，另含 1 位巡店扩展员工），Paihuo 内容生产部 10 位员工与 1 位 NanoWork 原生 AI 带货员进入内容生产仓；每位员工均有完整岗位运行包和对应业务入口。
- 七面板完整工作台：管理角色可查看每位员工的“单独派活、能力、工作方式、技能库、提示词、工作配置、岗位档案”；出厂核心能力和岗位 Skill 锁定启用，企业配置只能追加，不能削弱岗位合同。普通员工只看派活、进度和授权结果。
- 岗位专属派活：前台只要求“一句任务目标 + 可选素材”，服务端按岗位补齐任务类型、平台、规格、工具和交付检查项，不再把工程配置推给用户。
- 完整技能库：安全白名单快照保留 409 张技能卡，其中餐饮员工 344 张、Paihuo 内容员工 65 张；按老板确认状态默认启用并锁定进入执行，历史来源状态继续保留在审计字段中，不在业务界面显示“待核验”。
- 统一文件输入：派活时可从本企业文件中心选择最多 6 个附件；服务端校验租户、用户权限和文件有效性，只把可读取内容作为不可信资料注入。另可附 1 张 PNG、JPEG 或 WebP 内联图片，原图不写入任务快照。
- 内容生产仓：10 位 Paihuo 员工覆盖趋势、情报、拆解、撰稿、文风、视觉、封面、演绎、分发与复盘，第 11 位原生 AI 带货员负责图片素材到 30 秒带货视频。独立 AI 图片/视频/PPT 入口从主界面隐藏，底层能力和历史数据仍保留供岗位调用。
- 内容任务闭环：支持手动创作、立即自动执行、每日定时和每周定时；员工与任务类型必须匹配。来源、岗位契约和账务合格的低风险内部产物自动采纳；高风险、外发、付费或不可逆动作强制老板门禁。任何路径都不会自动发布。
- 素材真实引用：一次创作可选择最多 6 份本企业可见素材。服务端注入已持久化正文或明确的文件引用，生成成功后才写入引用关系并增加使用次数；任务快照保留不可变素材快照与哈希，不能用一次点击冒充真实使用。
- 两阶段计费：内容文案、后台任务、PPT、图片、日更包、立即自动与定时自动均先做原子预授权；只有业务产物、审批、资产和引用在同一事务中落库成功后才结算。未交付全额退回，结算异常保留为待对账，页面不会把预授权冒充实扣。
- 自动任务安全：按上海时区计算计划时间，使用原子认领和唯一认领键避免并发重复执行；服务恢复时会把超时运行安全终止并记录失败，不会借恢复流程自动发布。
- 经营工具箱：11 个工具——今日必发、视频成片、私域日历、竞品盯梢、起号军师、线索雷达、产品图文、看图写卖点、链接转口播稿、口播矩阵，以及联网搜图。前 10 个由对应数字员工真实调用模型并按量计费（失败轮次退款、可免费重试；产品图文的矢量叠字不计费），联网搜图的公开搜图与素材导入不扣积分；未配置模型时只给出明确标注为模板的底稿，结果页如实标注执行模式。
- 经营洞察闭环：统一筛选餐饮员工任务、内容员工单独派活、内容成品与工具运行记录，并可穿透到输入、产出原文、岗位修订、提示词哈希、能力、配置、技能、附件证据、联网证据和审批边界。
- 账号安全：账号采用可恢复的软停用，保留用户 ID、历史内容、任务、审批和运行归属；停用时同步关闭其仍启用的内容自动任务，并保护当前账号、平台超级管理员和企业最后一个老板/管理员。

数字员工和工具产出按平台超级管理员锁定的企业策略验收：真实来源、岗位契约和账务都合格的低风险内部产物可自动采纳；高风险、对外发布、付费或不可逆动作强制进老板门禁。系统不会自动发布内容、修改价格、采购、排班、处罚员工或代表企业作出外部承诺。

## 本地启动

### 其他电脑一键使用（推荐）

先安装 [Node.js 24 LTS（含 npm）](https://nodejs.org/en/download) 和 [Git](https://git-scm.com/downloads)。首次获取项目：

```bash
git clone https://github.com/wl13643464077-dev/nanowork-enterprise.git
cd nanowork-enterprise
```

- Windows：双击根目录 `start.cmd`；以后关闭原服务窗口，再双击 `sync-start.cmd` 同步 GitHub `main` 并启动。
- macOS / Linux：首次 `npm run local:start`；以后停止原服务后 `npm run local:sync`。
- 脚本自动安装锁定依赖、构建、初始化、检查健康状态并打开登录页；请保留启动窗口，Ctrl+C 关闭。
- 新电脑首次生成自己的 `guan`（老板）和 `super`（平台管理）账号，独立随机密码仅保存在本机私有文件 `server/data/local-first-login.txt`，不会打印进安装日志或上传 GitHub。建议先用 `guan`，并及时修改初始密码；首次开店向导属于正常初始化。
- 已有 `server/.env`、数据库和账号密码保持不变。升级启动前自动生成私有 SQLite 一致性备份并校验；端口占用、源码有未提交改动、不是 `main` 或不能快进合并时明确停止，不强制覆盖或结束其他进程。
- GitHub **只同步程序，不同步账号、密码、API 密钥或业务数据**。不同电脑初始化的同名账号密码不同。如需多电脑共享同一企业数据，应连接同一部署好的服务，不能用 Git 同步 SQLite 或复制正在运行的 DB/WAL 文件。
- ZIP 下载也可双击 `start.cmd` 安装启动，但不能直接 Git 更新；需要自动更新请使用上面的 `git clone`。

视频合成另需 ffmpeg/ffprobe，可安装到 PATH 或在 `server/.env` 设置 `FFMPEG_PATH`、`FFPROBE_PATH`。真实 AI 生成需单独配置自己的服务端供应商密钥；未配置时不代表已完成真实云端视频验收。一键脚本不会下载/执行未知安装器、自动开公网、启用定时收费任务或修改系统代理。

### 手动启动

运行要求 Node.js 22.12+；Windows 和一键脚本统一使用 Node.js 24。

```bash
npm --prefix server ci
npm --prefix web ci
npm run build

# 首次安全初始化（已有账号不改动）
node scripts/local-setup.mjs
npm start
```

浏览器打开 [http://127.0.0.1:3107](http://127.0.0.1:3107)。新项目固定使用独立默认端口 `3107`，不占用、停止或重启现有项目的 `3007` 服务。

首次账号密码见本机 `server/data/local-first-login.txt`。直接运行 `npm start` 的传统流程仅保证平台超级管理员初始化；密码由首次 `PLATFORM_SUPER_PASSWORD` 配置或独立数据库决定，没有适用于所有电脑的固定密码。不要对已有业务库开启 `SEED_DEMO`。

本地自定义配置可先执行 `cp server/.env.example server/.env`。模板默认为 `development`，AI 和飞书凭据均留空。生产环境禁止启用 `SEED_DEMO`；`JWT_SECRET` 必须是至少 32 字节的强随机串，首次初始化的 `PLATFORM_SUPER_PASSWORD` 必须至少 12 位且包含四类字符中的至少三类。

前后端分离开发：

```bash
npm --prefix server run dev
npm --prefix web run dev
```

## 验证

```bash
npm run verify
```

`verify` 依次运行后端测试、前端 TypeScript 检查、多租户隔离扫描、设计令牌与界面契约检查、lint、格式检查与生产构建。Windows 本机运行全量验证需要 Node.js 24 与 ffmpeg/ffprobe（视频合成与样片导入测试依赖；可通过 `FFMPEG_PATH` / `FFPROBE_PATH` 指定路径），部分依赖 POSIX 权限位或 macOS 路径的用例在 Windows 上属于已知环境差异。验收重点包括：餐饮 61 位（60 位核心 + 1 位扩展）、10 位 Paihuo 内容员工与 1 位 NanoWork 原生 AI 带货员的完整岗位包、七面板工作台、极简派活、文件权限与附件快照、联网/知识库证据、策略验收、15 项内容连接器、30 秒视频、自动任务调度与恢复、账号软停用、权限隔离和前端生产构建。最终结果以本机当次命令输出为准，不在文档中固化易过期的测试数量。

服务启动后还可对当前运行实例做只读验收：

```bash
NANOWORK_ACCEPT_USERNAME='管理账号' \
NANOWORK_ACCEPT_PASSWORD='对应密码' \
npm run accept:runtime
```

该命令会实际登录并逐个核对餐饮 61 位员工（60 位核心 + 1 位巡店扩展）、10 位 Paihuo 内容员工、岗位专属派活指引、内容部门目录、每日/每周自动任务及禁止自动外发边界。AI 带货员的专用视频链由 `ai-sales-video` 专项测试与媒体验收门单独覆盖。

## 数据与安全边界

- 默认数据库：`server/data/nanowork-industry.db`。
- 3107 本地预览数据库：`server/data/nanowork-preview.db`，通过 `NANOWORK_DB` 显式指定。
- `server/.env`、数据库、日志和构建产物均被忽略，不应提交。
- 内容生成、立即自动执行和定时执行都不会自动发布。命中风险或配置为全部审核的结果须审批通过；无风险且规则允许的结果可进入“可使用”，但导入、对外发布和效果登记仍由有权限人员明确操作。
- 内容生产按单员工、单岗位任务执行，不把尚未真实执行的阶段展示成自动十工位流水线。
- 撰稿人 #3、多媒体师 #5、演绎师 #7 的文案/媒体/PPT 连接器是附加入口，不替代其完整岗位能力；演绎师仍以 HTML 为主交付。
- 食品安全、财务、法律、隐私和外部执行事项必须由授权人员复核。
