# 积分、供应商成本与公网部署（2026-09-06）

## 用户确定的规则

1. 成功交付按上游钱包实际扣费（使用上游公开人民币换算）× 2 收取；积分单价默认 0.01 元，向上取整到积分。成本 2 元对应用户 4 元、400 积分。
2. 最终生成失败且没有可交付成果，用户本次积分全退；供应商已经扣取的成本由平台承担。
3. 已经保存的正文、图片或视频，不能因结算回执异常被丢弃或再次付费生成。此时保留结果、费用待核对。
4. 一次付费开通一个主账号，包含四个副账号；额外席位走申请与支付，开通费、席位费、充值积分分别按购买时冻结的套餐权益执行。
5. 服务器每月不超过 500 元；用户已选“纳米work.cn”，99 元/年。

## 本次账务修改

- 预授权保存定价快照。管理员中途修改模型价格、积分单价或倍率，不追溯改变该任务的结算口径。
- 对合法供应商实际费用回执使用实际费用 × 2；拒绝负数、非有限数字、非法 token、伪造或算术不一致的费用信息。新 upstream_debit 策略超过参考预占时原子补扣差额；余额不足时保留成果与原预占等待核账。旧 hold 继续遵循冻结报价，不追改。
- 最终失败退款使用统一原子事务。重复退款幂等，跨租户和过期执行者不能退别人的任务。退款和供应商成本分别记账；未知成本标记待核，不再写成已知零成本。
- 已结算任务退款保留原始消费流水，另建退款流水；后补供应商回执只补平台成本，不重新扣已退款用户。
- 充值回调校验订单渠道、商户身份、币种、金额与交易号；重复回调不重复入账。购买时冻结套餐价格和权益，后续修改套餐不影响原订单。
- 平台手动充值和开通支持稳定请求键、防重复提交与事务审计。
- 统一两阶段执行器先保存成果再结算。缺少有效计费用量时保留成果待核对；模板或非真实模型的独立真实性校验仍保留。
- 原生带货视频、逐张小红书图片的失败退款与免费取回边界已补测；成功文件保留，退款后不能自动重新付费生成。

## 上游实际扣费核验与启用

用户最新确认定价依据是上游 API 钱包逐请求的实际消耗，不是采购充值支付的人民币金额。已删除充值实付、到账额度和凭据三项前置配置，生产及本地均已启用 `{enabled:true,basis:'upstream_debit'}`，售价倍数固定 2，积分面值 0.01 元。

通过 OpenLux 的实际扣费 `quota` 与 `/api/status` 公布的 `quota_per_unit=500000`、`usd_exchange_rate=6.744675` 核算。已核对一笔真实 Wan 视频账单：322544 quota 折合 4.3509089064 元，应结算 871 积分；这只是验算，未追改历史客户扣费。

实测发现 OpenLux 返回 `x-api-request-id`，旧版漏读；现已统一文本、图片、视频的网关请求编号，并兼容旧头。修复后新发一次独立小额真实请求，返回 `5`，精确匹配上游账单并在隔离账本验证实际计价、重复不扣与失败全退，9 项均通过。首次回执匹配失败的证据单独保留。完整过程见 [本轮实际扣费说明](2026-09-06-upstream-debit-pricing.md)。

回执按请求编号与模型精确匹配，合并任务要求每次调用均有凭证，同一回执不能被不同账单重复使用。缺失、重复或冲突回执保留成果待核对。免费重查不重新付费生成。其他供应商仍需各自的真实回执接入，不能标为 OpenLux 实际费用。没有更改历史客户余额或扣费。
