# 上游实际扣费结算规则

日期：2026-09-06

本地与正式网站均已启用上游实际扣费 ×2。生产 release 20260906183112，启用时间为 2026-09-06T10:32:06Z。下文记录计价规则、真实调用、隔离账本和部署验证。

## 计费口径

用户在产品内充值算力余额。每次 API 请求按上游钱包的实际扣费回执核算，将上游扣费金额按上游公开的人民币换算汇率折算，再乘固定售价倍数 2，从用户算力余额结算。

当前 1 积分对应人民币 0.01 元，扣减积分按现有精度向上取整：

```text
扣减积分 = ceil(上游实际扣费折合人民币 × 2 ÷ 积分单价)
当前积分单价 = 0.01 元/积分
```

例如，上游一次请求实际扣费折合人民币 2 元，用户结算金额为 4 元，即 400 积分。

上游采购额度时的人民币实付、到账额度、充值优惠和充值凭据，不再作为启用或结算的前置条件。模型手动价格用于预占估算，以及尚未接入真实回执的供应商参考计价；实际扣费模式下，参考价不能替代所需的真实回执。

## 价格快照与余额处理

- 以原始预占记录（hold）的冻结策略和价格快照为准。调整配置不追溯改写旧 hold 的计费口径，也不重算已结算账单。
- 新的上游实际扣费策略标识为 `supplierCostPolicy.basis = 'upstream_debit'`。该模式的售价倍数固定为 2；当前积分单价沿用配置值 0.01 元。
- 实际应扣低于预占时，退回差额。符合上游实际扣费策略且真实回执已经核验时，超过预占的部分原子补扣。
- 余额不足以补差时，不先完成部分扣款，不将已有结果丢弃；保留结果及待结算状态，等待余额和账务条件满足后处理。
- 手工核账和流水线核账中的旧参考价结算路径，不得绕过新 hold 的真实回执要求。被阻断时提示保留结果、核验上游回执，不引导重新生成。

## 失败、回执与重复请求

- 最终生成失败、没有可交付成果时，用户该任务扣款全额退还。上游已经发生的支出由平台承担，供应商支出记录与用户退款分开处理。
- 上游是否扣费尚不明确，不应成为无限期冻结用户失败任务资金的理由；供应商费用可以保持待核验。
- 真实回执按供应商与请求标识唯一归属，防止同一回执被不同账单重复使用。重复结算或退款保持幂等。
- 回执迟到时，只进行不产生新模型费用的查账与核验。补录已退款任务的供应商费用，不再次扣减用户积分。
- 不自动重新发起付费生成。已有结果应保留，回执待核和余额不足应通过查账或结算处理，不通过再次生成解决。

## 管理端配置

“上游实际扣费”面板保留启用开关，提交 `supplierCost: { enabled, basis: 'upstream_debit' }`。已删除人民币实付、到账美元额度、充值凭据说明三项输入。

启用时，“售价倍数”固定显示 2 且不可编辑，提交的计费配置也强制为 2。关闭时显示参考计价配置，并允许编辑参考倍数；切换及其他配置修改需保存后生效。积分单价沿用配置，不因开关切换而更改。
