# 邀请码注册交付

用户要求已落实为完整的发码、核验、注册、登录流程。邀请码决定账号进入哪家企业、获得什么角色；注册人只填写自己的资料，不能取得平台接口或密钥管理权限。

本轮后续已增加[主副账号与付费扩容](2026-09-05-paid-seat-expansion.md)：新企业首位老板绑定主账号，基础5席位明确为1主4副；成员邀请码只占副账号额度，追加名额须先付费开通。下方验证记录为邀请码初版的历史验收。

## 使用

1. 平台超级管理员登录后，在“邀请码”页选择“开通新企业”或“邀请企业成员”。新企业注册人固定为老板；已有企业可以指定成员角色。
2. 企业老板或管理员在“管理后台 → 邀请码”邀请本企业成员，可指定老板、管理员、运营负责人、店长、员工或推广伙伴。普通成员不能管理邀请码。
3. 点击“生成邀请码”，复制邀请码或邀请链接交给注册人。默认只能使用一次，7天内有效；“更多选项”可调整1–50次、1–90天。
4. 注册人在登录面板点击“邀请码注册”，或直接打开邀请链接。核验后显示固定的企业与角色，填完资料即可注册并登录。新企业需要填写企业名称；加入已有企业不需要重复建企业。
5. 未使用的邀请码可停用。完整原码只在创建时显示，刷新后只显示掩码；忘记保存时停用后重新生成即可。已注册账号继续按原账号管理规则管理，停用邀请码只阻止后续注册。

没有邀请码的人仍可使用“申请开通”，审核后登录。新企业邀请码创建的企业直接开通，默认标准版标签、5个席位、0积分，不自动激活付费套餐或赠送积分。账号开通和AI消费额度分开管理。

本机地址生成的邀请链接仅适用于能访问该服务的设备；正式部署后在实际企业服务地址生成、使用邀请链接。链接使用 `#invite=`，原码不放在HTTP查询参数中。

## 实现与权限

- `invitations` 保存随机码的SHA-256摘要、掩码、绑定企业和角色、次数与有效期；`invitation_events` 在同一事务中记录创建、停用和兑换。迁移幂等，不生成真实邀请码。
- 创建原码具有192位随机性，只有创建响应包含完整原码。列表、预览及审计不返回原码或哈希。
- `/api/platform/invitations` 只允许平台超级管理员；`/api/admin/invitations` 只允许已开通企业的老板和管理员操作本企业。
- 兑换重新检查邀请码、发码者当前身份与启用状态、企业状态、门店归属、席位、账号唯一性。校验、计次、创建企业/账号和审计使用同一写事务。
- 重复用户名、席位不足或审计写入失败都回滚，原码可继续使用。一次性邀请码的并发请求仅允许一个注册成功。
- 显式提供空码或无效码不会降级为普通注册。公共预览与注册有按IP限流，响应禁止缓存。修改邀请码后旧预检立即失效，过时异步响应不能恢复旧企业信息。
- 邀请码注册与普通企业申请分开限流：默认同IP每小时60次与5次，避免同一办公网络第六位成员被普通申请额度挡住。带码请求的空码、换码、格式错误同样计数，超限返回429及Retry-After，预览额度独立。
- 企业及成员继续使用已有模型目录和岗位权限；不能读取、更换API、提取密钥、跨企业操作或增发积分。
