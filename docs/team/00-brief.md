# 升级迭代产品简报

日期：2026-07-31

产品一句话：把纳米Work升级为老板、管理层和员工能在同一条真实业务链上派活、执行、审阅、追踪结果，并具有成熟产品质感的企业数字员工工作台。

目标用户：企业老板、管理员、部门员工，以及维护平台租户与计费的平台主管。

核心痛点：

- 同一数字员工在不同执行入口能力不一致。
- 模板底稿被误认为真实交付。
- 外部 AI 调用、调度和密钥处理存在生产风险。
- 角色入口、数据范围和经营指标存在明显业务错误。

目标动作：模拟老板、运营管理层和一线员工逐项操作，关闭任务、审批、内容与资产流向中的断链；重构全局视觉壳层与核心工作台；最后以真实应用 API、受控云模型样本和真实浏览器证明结果成立。

成功指标：

- 启动无显式开关时不会运行自动化。
- 密钥不写 SQLite，错误不泄露凭据。
- 员工配置真实控制模型、长度、超时与联网行为。
- 严格岗位契约拒绝空值和错类型。
- 未完成底稿不计成功产出。
- 销售读取老板日报返回 403。
- 目标缺失时不显示伪百分比。
- 角色入口与后端权限一致。
- 全量测试、类型检查和构建通过。
- 老板会诊形成的任务有明确接单人、下一步和终态，不再永久停在“执行中”。
- 数字员工产出只有一个权威审核入口；任务、内容、审批、知识与资产状态同步改变。
- 人工任务只允许“待执行 → 进行中 → 提交待审核 → 审核完成/退回”的合法转换。
- 老板、运营和一线员工分别完成真实页面与真实应用 API 验收；代表性云模型结果必须明确为 `api`，不得用模板降级冒充。
- 全局壳层让主内容成为视觉主角；数字员工、内容生产仓和任务看板呈现活的任务轨迹与结果，而不是等权静态卡片。

交付等级：当前新项目内可运行、可回归的升级版本；本轮不对外发布。

硬约束：

- 不修改旧项目。
- 不覆盖用户现有未跟踪文件。
- 用户已明确授权受控真实 API 验收；只允许代表性的文本模型样本，调用前设停止条件，不调用图片、视频、支付、飞书发送或外部发布。
- 密钥只允许进入临时进程环境，不写仓库、数据库、日志或报告；已暴露的旧密钥不得静默复用，真实云验收需轮换后的测试密钥。
- 不执行 Git commit、push 或发布。

未知风险：统一外部调用和员工执行链可能触及较多历史入口；按垂直切片小步迁移，未迁移入口必须明确保留为发布阻断。

## 2026-08-10｜派活式对话员工与文件交付

用户目标：数字员工不再以“能力、提示词、API、岗位档案”等后台配置作为主界面，而是以一句话对话为唯一公开入口。系统在后台按员工身份自动装载岗位手册、Skills、知识库、联网、地图、工具和模型；执行过程可视化；完成后直接显示可读报告，并按产物语义提供 PDF、Word、Excel、PPT 或原生文件下载。

本轮必须解决：

- 单个数字员工对标派活的 `任务消息 → 后台岗位包/技能 → 真实执行进度 → Markdown 报告 → 文件下载` 全链，而不是要求用户理解或配置内部能力。
- 真实模型已经生成非空内部报告时，普通完整度、篇幅、字段数量等机器质检只作建议，不再清空正文或把演示任务判死；无真实 API、空输出、内部档案泄漏、伪造来源、越权或外部不可逆动作仍必须阻断。
- 报告和附件刷新后仍可从任务来源找回；下载由服务端按任务 ID 读取权威正文生成，不能信任浏览器重新提交的任意正文。
- 内容单岗和 0→9 内容团队使用同一公开交互模型：对话输入、真实阶段、报告、附件。普通内部生产默认自动流转；外发、付费和不可逆动作仍需独立授权。

本轮成功指标：

- 餐饮与内容单岗公开工作台只展示对话、执行过程、报告和下载；内部能力只保留在次级管理入口。
- 演示租户在真实 API 有正向 token 且报告非空时能看见并下载内部草稿；live 租户仍执行严格策略。
- PDF/DOCX/XLSX/PPTX 均为真实文件格式、租户隔离、带稳定下载文件名；任务刷新后仍能找回。
- 内容团队公开入口默认 `internal_auto`，不会因普通人工审阅停在第 8 工位；系统不会自动对外发布。
- 本地 3107 浏览器完成至少一条“对话 → 进度 → 报告 → 下载”可见验收，自动化和工程门全绿。

已跳过阶段及原因：市场压力测试与用户研究已跳过，本轮是现有产品的证据驱动缺陷升级。
