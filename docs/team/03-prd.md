# 角色任务闭环、业务穿刺与界面重构 PRD

日期：2026-07-31
模式：自动执行
交付：新项目内可运行、可回归、可由三角色实际操作的本地版本

## 问题陈述

当前产品拥有大量功能和数据，但三类问题叠加后让用户不信任它：业务状态能从多个入口被不同方式修改；任务、审批、内容、资产与经营结果之间缺少统一穿刺；界面由常驻四向 chrome、等权白卡和小字号堆叠，像静态后台模板，不能表达数字员工正在工作。

## 目标用户与核心结果

- 老板：看清经营问题，把工作交给管理层或数字员工，最终能看到谁做了什么、谁审了、产物去了哪里。
- 运营管理层：接收老板目标，继续分派、审阅低风险结果并推动员工执行，但不能查看数字员工内部岗位档案。
- 一线员工：只看到本人任务，按合法状态提交结果，不能越权完成任务、审核数字员工结果或读取管理信息。

## 主用户路径

1. 老板从驾驶舱、老板参谋或数字员工目录发起任务。
2. 管理层接单、拆解或选择岗位；一线员工或数字员工执行。
3. 系统持续显示运行状态、输入、负责人、时限、业务产物和下一动作。
4. 结果进入唯一权威审阅流程；高风险必须由老板终审。
5. 审阅结果在同一事务内同步到任务、内容、审批、知识与资产。
6. 任一对象都可打开业务穿刺，回看到来源、执行、审阅、产物、下游与经营证据。

## 功能需求与验收标准

### FR-1 三角色真实验收

- 老板、运营、一线员工分别登录并逐个打开其可见一级入口；无登录回退、空白页或控制台错误。
- 老板完成一次参谋诊断和一次数字员工派活；运营完成一次派活/审阅；一线员工完成一次人工任务开始、提交，运营完成审核。
- 真实云样本只计 `aiMode=api` 且模型与角色/岗位路由一致；模板降级、契约无效、悬挂占扣均判失败。

### FR-2 唯一审批命令

- 餐饮数字员工的工作台审核与审批中心调用同一个领域命令。
- 普通员工审核返回 403；高风险运营审核返回 403；重复处理幂等。
- 通过或驳回后，审批单、内容和员工任务状态一致；通过只生成一份知识/资产记录。

### FR-3 人工任务状态机

- 员工不能绕过提交直接进入待审核或完成；管理层不能直接把未提交任务改成完成。
- 只有最新待审核提交可被处理；审核人、时间和理由可审计。
- 驳回回到可继续执行状态；已完成重新打开必须使用独立动作并填写原因。

### FR-4 老板参谋到执行

- 会诊转任务按明确执行人匹配同租户用户；无法匹配时交给运营负责人而不是老板本人。
- “转派数字员工分部”不得创建永久执行中的假任务；它必须形成可接单的管理任务，携带来源会诊、目标分部和继续派活入口。

### FR-5 统一任务中心与业务穿刺

- 任务中心同时提供人工经营任务和数字员工任务两个清晰视图，不混用状态词。
- 数字员工视图聚合餐饮任务、内容员工运行、审批、内容/素材和资产，并按角色范围分页筛选。
- 穿刺返回稳定节点：来源 → 派发 → 执行 → 审阅 → 产物 → 下游；每个节点显示状态、时间、负责人、证据和下一动作。

### FR-6 安静经营指挥台

- 桌面默认只保留可折叠导航与主内容；右助手按需打开，底部快捷栏并入命令面板和页面主动作。
- 页面标题、状态、筛选和主动作位置统一；每页只突出一个主动作。
- 数字员工、内容仓和任务看板优先显示任务、轨迹和产物，档案与说明进入次级 inspector。
- 375px 窄屏可完成主要路径；正文不小于 13px；键盘焦点、加载、空和错误状态齐全。

## 非目标

- 本轮不自动对外发布，不调用图片或视频生成，不执行支付、飞书发送和生产部署。
- 不一次性重写全部 15 个页面；先以全局令牌/壳层覆盖全站，再深改老板驾驶舱、数字员工、内容生产仓与任务看板。
- 不把十个内容工位包装成已经自动串行的流水线；本轮先交付真实状态、审阅与穿刺，再以独立切片实现跨工位工作流。

## 成功指标

- 新增状态机与穿刺专项全部通过，全量 `npm run verify` 通过。
- 新创建测试数据不存在“完成任务+待审核内容”“待审核内容无审批”“待审核人工任务无提交”等不变量破坏。
- 三角色真实页面与应用 API 矩阵全绿；受控云样本无模板降级、无悬挂占扣、无外部发布。
- 1280px 桌面主工作区占视口宽度至少 70%，不再由常驻右栏和底栏挤占。

# 2026-08-08｜数字员工免审、最简派活与 AI 带货员升级 PRD

> 本节是当前需求的增量权威口径；与前文“所有数字员工产出必须进入人工审阅”冲突时，以本节为准。人工经营任务的提交/审核状态机不在本次删除范围内。

## 目标

- 老板只需说清“这次要解决什么问题”并按需上传资料，岗位自行补齐执行计划、工具、联网、知识库与交付格式。
- 普通数字员工任务完成机器契约、事实与安全门后直接成为可用结果，不再堆积为“待审阅”。
- 超级管理者可按企业配置哪些结果免审、哪些由负责人/老板审批；高风险、付费和对外动作继续保留不可关闭的安全门。
- 现有 60 名餐饮员工与 10 名 Paihuo 内容员工执行时完整装载能力、工作方式、技能库、提示词、工作配置、岗位档案、API、工具、知识库与联网策略，不因前台简化而削弱能力。
- 内容生产仓由“能力入口列表”回归“数字员工队伍”：保留 10 名 Paihuo 员工，新增 1 名本项目原生的“AI 带货员”；独立 AI 图片、AI PPT、AI 视频入口从主导航移除，底层媒体能力仍供岗位调用。

## 核心用户路径

1. 用户选择数字员工，只填写一句任务目标；行业、门店、商圈等上下文优先从企业档案、门店档案和知识库自动补齐，可选上传图片或文件。
2. 运行时生成 `resolvedBrief`，列明已自动补齐内容、将调用的技能/知识/联网/地图/模型及仍缺失的关键事实。
3. 岗位按完整 canonical profile 执行；需要最新、地域或竞争情报时自动联网，需要企业事实时自动检索授权知识库。
4. 低风险内部产物通过机器质量门后直接进入“已完成 / 可使用”；只有策略命中或安全底线命中时进入审批中心。
5. AI 带货员接收人物、菜品/商品、门头等图片与一句卖点，先生成 30 秒脚本和三段分镜，再调用已授权视频供应商生成 3×10 秒素材并合成为一个 30 秒视频。

## 功能需求与验收

### FR-U1｜超级管理者审批策略

- 数字员工产出新增 `auto`、`risk_based`、`manager`、`boss` 四类策略；新企业默认 `auto`。
- `auto` 只对低风险内部产物免审；高风险、真实付费、对外发布/发送/账号操作仍强制老板侧确认。
- `platform_super` 可配置；老板/管理员只读查看当前规则与原因；运营和员工不可修改。
- 免审结果不创建伪审批单，任务、内容、资产与知识状态在同一业务事务中收敛；重复回调不重复沉淀。
- 历史“待审阅”记录不批量伪造为已完成，保持可审计并提供明确处理入口。

### FR-U2｜完整岗位运行包默认启用

- 70 名既有数字员工的 canonical profile 必须包含并执行：`identity`、`capabilities`、`workMethod`、`skillLibrary`、`prompts`、`workConfig`、`jobProfile`、`runtimeBindings`、`contracts`、`permissions`。
- 老板已核验的历史技能默认 `enabled=true`，不可被派活表单意外关闭；前台不再出现“历史技能待核验”“折叠后未启用”等误导文案。
- 保留来源、版本和指纹审计；“老板已确认可用”不等同于对第三方平台规则和实时业务效果作永久保证。
- 老板侧继续可查看完整七面板；运营和员工仍只见岗位摘要、派活、进度与业务结果。

### FR-U3｜最简派活

- 通用必填项仅保留一句 `任务目标`；附件、截止时间、输出偏好均为可选。
- 行业、门店、位置、品牌、客群、历史数据、知识范围、联网方式、模型、篇幅、技能选择由岗位和租户配置自动解析，不要求用户重复准备清单。
- 地域/商圈任务自动从门店档案取位置并调用已配置地图/联网工具；若缺少唯一不可推断的关键事实，只提出一条聚焦补充问题，不把工程字段暴露给用户。
- API 返回原始输入和 `resolvedBrief`，可追踪每项补齐依据，不允许模型暗中把猜测写成事实。

### FR-U4｜联网、知识库与外部模型

- 每名员工默认拥有联网和知识库运行绑定；是否实际调用由岗位 `webRequired`、任务时效/地域语义和数据新鲜度决定。
- 联网来源必须保存标题、URL、摘要、时间与归因；没有证据时明确失败或列待补事实，不编造来源。
- 知识检索只使用当前租户、当前角色授权范围；跨租户、无权限和未启用知识不得进入提示词。
- 外部连接器区分“可用、待凭证、验证失败、已禁用”，不能把目录存在或 API Key 存在显示为已连接。

### FR-U5｜内容生产仓信息架构

- 首页直接展示 10 名 Paihuo 员工与 1 名 AI 带货员，岗位卡片以“能解决什么、最少输入、交付什么、当前可用状态”为主。
- 主导航移除独立 `AI图片`、`AI视频`、`AIPPT` 页签；相应路由/处理器作为多媒体师、演绎师和 AI 带货员的底层能力保留。
- 旧深链在兼容期跳转到对应数字员工派活界面，不能出现 404 或丢失历史任务。

### FR-U6｜AI 带货员 30 秒视频

- 最少输入：一句带货目标 + 至少一张人物、商品/菜品或门店图片；支持多图分类与预览。
- 输出包包含：事实清单、30 秒口播稿、三段分镜、字幕、封面建议、三段视频状态、合成视频、供应商/模型/用量/费用证据。
- 目标模型为最新 `MiniMax-H3` 多模态视频；在 H3 计价与当前代理路由未由超级管理者验证前明确显示“待开通”，可由管理员选择已核价的 `MiniMax-Hailuo-2.3-Fast/2.3` 作为兼容回退，不静默换模。
- 供应商采用异步创建、轮询、文件获取；H3 单段支持 4–15 秒，30 秒按两段 15 秒（H3）或三段 10 秒（Hailuo 2.3）合成。任一段失败可定向重试，不重复扣已成功分段。
- 未配置凭证或未取得付费授权时，系统停在“待开通/待授权”，仍可生成不付费的脚本与分镜，但不得返回伪视频 URL 或伪装完成。

## 非目标与安全边界

- 不删除人工经营任务审批；不关闭食安、金额、隐私、付费和对外发布安全门。
- 本轮不使用会话中曾暴露的任何密钥，不在代码、SQLite、日志或文档中保存供应商密钥。
- 未经单独费用授权不发起真实视频生成；以可注入传输层、契约测试和本地合成样本验收接入正确性。

## 成功指标

- 普通低风险数字员工样本 100% 不进入待审队列；策略命中与高风险样本 100% 进入正确审批路径。
- 70 名既有员工运行快照 100% 证明完整 canonical profile、全部必备能力、已启用技能、联网与知识库绑定已装载。
- 两类工作台的默认派活必填字段均不超过 1 个文本目标；附件可选。
- 内容仓主入口只保留数字员工、素材/模板/任务等业务入口，不再把图片/PPT/视频当作并列产品。
- AI 带货员在无凭证环境完成脚本、分镜、授权阻断和任务可恢复；在模拟供应商下完成 3×10 秒生成、轮询、合成、落库与幂等回归。
- `npm run verify`、角色权限专项、审批策略专项、70 人运行包专项和内容媒体专项全部通过。
