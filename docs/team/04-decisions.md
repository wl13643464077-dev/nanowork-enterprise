# 决策记录

## D-001｜密钥只做进程级临时注入

- 日期：2026-07-30
- 决策：不通过管理后台保存密钥，不创建 `server/.env`，只给本次服务进程注入。
- 原因：当前后台保存会把完整密钥以明文写入 SQLite；界面掩码仅是回显掩码，不是加密存储。
- 结果：工作树、原演示库和隔离测试库的 `sys_config` 均无云雾密钥记录。

- 结果：原演示库回到测试前基线；隔离测试库关闭全部自动化后用于页面验收。

## 修复后迭代结果（决策）

> D-001 至 D-013 为修复前基线与本轮开工决策，继续保留；以下决策记录实现与发布收口后的当前口径。

## D-014｜联网检索必须在预授权之后执行

- 日期：2026-07-30
- 决策：`webRequired` 岗位先完成权限、余额预检和可追踪占扣，再调用检索服务；没有可引用证据即停止，不调用生成模型。
- 原因：检索本身属于外部成本，不能在余额检查前调用，也不能用模型记忆冒充实时证据。
- 影响：内容员工手动、立即和定时路径均保留检索供应商、来源标题、URL、摘要和失败原因快照。

## D-015｜后台 AI 并发租约保持到真实终态

- 日期：2026-07-30
- 决策：所有响应后继续运行的后台 AI 任务必须调用 `req.aiGuard.defer()`，并在成功、失败或异常终态的 `finally` 中释放。
- 原因：HTTP 响应完成不等于上游任务完成；提前释放会让并发保护失真。
- 影响：内容后台生成和内容员工后台派活均有生命周期回归测试。

## D-016｜业务产物先落库再结算

- 日期：2026-07-30
- 决策：内容员工运行必须先可靠落库完整产物与待结算快照，再结算占扣；落库失败全额释放，结算失败保留产物并标记 `pending_reconciliation`。
- 原因：禁止出现“积分已扣但业务交付不存在”。
- 影响：成功、落库失败、结算失败三条路径都有独立自动化证据。

## D-017｜采用三级发布结论

- 证据：最终自动化测试 `456/456` 通过，0 失败。

## D-020｜内容自动化采用可追踪异步契约

- 日期：2026-07-30
- 决策：立即执行返回 `202 + runId + pollUrl`，客户端按 `runId` 精确轮询；同一次运行幂等复用，手动与定时领取统一执行租户、员工和 `content` 模块撤权门禁，费用估算、占扣与生成使用同一实际模型。
- 原因：HTTP 接单不等于任务完成，且授权或模型口径在排队期间漂移会导致越权、重复执行或计费不一致。
- 影响：内容自动化具备稳定终态、重复提交保护、执行时授权复核和一致的成本证据。

## D-021｜支付结果必须唯一、绑定且新鲜

- 日期：2026-07-30
- 决策：支付报文拒绝重复关键节点，渠道结果必须绑定当前本地商户订单；微信签名响应只接受五分钟内的时间戳。
- 原因：重复字段、订单错绑和陈旧签名响应都可能把攻击或其他订单结果误判为当前交易成功。
- 影响：支付状态机在自动化层具备节点唯一性、订单关联性和响应新鲜度证据；真实渠道仍须沙箱/生产验收。

## D-022｜RAG 后台任务使用完整成本与生命周期保护

- 日期：2026-07-30
- 决策：RAG 后台任务在执行前预授权，按真实用量结算，与其他 AI 路径共享并发额度；超时必须释放资源，服务重启后恢复可恢复任务。
- 原因：后台响应结束不代表计算结束，独立并发池、估算即结算或无恢复机制都会造成超卖、悬挂占扣和孤儿任务。
- 影响：RAG 的计费、并发、超时和重启路径均进入自动化回归；本轮本地代码 P0/P1 发布阻断据此关闭。

## D-023｜技能验证分层，不把目录验证冒充效果验证

- 日期：2026-07-30

- 原因：来源完整性、结构可执行性和业务效果是三类不同证据，不能用一次离线测试替代真实平台效果。
- 影响：前后端统一展示验证层级和证据，不再用笼统的 `legacy_unverified`，也不声称算法规则或平台表现已经实时验证。

- 影响：内容员工档案、执行快照和接口返回同一状态；本轮不调用真实平台、不自动发布。

## D-028｜“已配置”与“已验证连接”是两种状态

- 日期：2026-07-31
- 决策：运行就绪状态采用多维事实；只有实现完整、配置完整、已启用且存在与当前配置匹配的新鲜显式成功验证时，才允许使用“已连接”。
- 原因：API Key 或字段存在只能证明配置存在，不能证明网络、鉴权、模型、证书、接收人或外部动作可用。
- 影响：就绪 GET 严禁联网；后台与系统页统一显示 `configured_unverified / connected / blocked / manual_only / disabled` 等真实状态。

## D-029｜占扣终态只信任数据库权威记录

- 日期：2026-07-31
- 决策：结算和释放必须在事务内按 hold ID 回读权威租户、流水和金额，调用方快照只用于一致性校验，不能作为更新依据；恢复不得因租户停用或单条坏记录跳过其他开放工作。
- 原因：恢复输入可能陈旧或被错误拼装，直接信任会扩大为跨租户或错金额账本风险。
- 影响：加入双租户伪造、重复终态、停用租户和故障隔离回归；持久化人工对账、视频主动轮询和请求级幂等仍作为后续独立切片。

## D-036｜三角色验收分成真实应用链与受控云样本

## D-037｜审核与人工任务状态机只有一条权威路径

- 日期：2026-07-31
- 决策：餐饮数字员工的旧审核接口与审批中心复用一个领域命令；任务、内容、审批、知识库和资产在同一事务中改变。人工任务只允许“待执行 → 进行中 → 提交待审核 → 审核完成/退回”，通用编辑接口不能直接写终态。
- 原因：双审核入口和任意状态更新会产生“任务完成但内容待审核”“审批未关闭”“待审核却没有提交记录”等不可处理状态。
- 影响：员工不能自审；高风险结果只允许老板侧角色通过；重复审核幂等且不能重复建资产；人工审核保存审核人、时间和理由，完成后重开走独立有理由动作。

- 影响：老板/授权管理层可从根任务查看完整可见链；员工叶子流中的无权父链匿名化，不返回标题、状态、时间、链接或内部编号。

## D-044｜70+10 数字员工升级为 L5 真实云逐岗验收

- 日期：2026-07-31
- 决策：用户已明确授权真实云文本调用及相应 token 消耗，本轮废止“抽取三个云样本即可收口”的旧验收边界；60 名餐饮员工与 10 名 Paihuo 内容员工必须逐岗调用真实云 API。`template`、`failed`、契约无效、无主产物、账务未终态或未到业务审阅终态均不得计入通过。
- 原因：此前 70/70 证据是 `deterministic_mock` 的 L4 应用链验证，只能证明正式 HTTP、权限、契约、落库和审阅管线可运行，不能证明每个岗位在真实模型下能完成自身任务。少量代表性样本暴露了超时、事实越界和状态口径矛盾，说明抽样不足。
- 影响：新增可断点续跑、可控并发、保存模型/token/费用/时延/失败原因的 L5 运行矩阵；每个失败项按“复现→根因→修复→重跑”关闭。图片、视频、支付、飞书和外部发布涉及额外费用、凭证或不可逆动作，仍不实际执行，只验证缺凭证时明确阻断且不伪装成功。

## D-045｜历史演示异常只做严格、可审计的定向对账

- 日期：2026-07-31
- 决策：启动对账只能处理可由固定演示指纹识别、且不存在真实来源、已完成人工审阅、下游知识/素材/发布证据或未结算占扣的历史演示记录。对账把互相冲突的内容、审批、员工任务和自动化运行收敛到可解释的失败/驳回终态，写入系统原因与操作日志；不得删除历史记录，也不得批量改写真实业务数据。
- 原因：旧演示数据曾出现“质检未通过但仍在人工审核队列”“任务已完成但提交仍待审核”“自动化无有效产物却显示待审阅”等不可能状态。让用户继续点击必然得到 409 或无效动作，把这些记录继续当待办比保留错误现场更危险。
- 影响：对账必须幂等；真实 API 来源、有下游采用/发布证据、已完成审阅或仍有权威占扣的记录一律保护。预览库本轮定向收敛 6 条内容、6 条审批、2 条员工任务和 4 条自动化运行，普通任务与提交错位归零，所有变更均保留审计证据。

## D-046｜今日作战计划与待办数字必须来自实时权威状态

- 日期：2026-07-31
- 决策：老板驾驶舱、管理层协同台和员工工作台中的今日作战计划、待审核数、任务状态与版本文案，必须由当前数据库权威状态和角色范围即时投影；种子期的“8 条待审”、旧版 `v2` 状态文案或静态摘要不得继续充当实时经营事实。
- 原因：静态演示数会在审批、驳回、迁移或角色切换后失真，让老板以为仍有待办，让员工看到不属于自己的任务，也会与审批中心、内容生产仓和任务看板互相打架。
- 影响：实时聚合与页面文案进入服务端回归和三角色浏览器门禁；数字必须能追溯到同一角色范围下的内容、审批、员工任务和普通任务权威行。无法从权威数据确认时显示“暂无/待同步”，不能伪造固定数量。

## D-047｜content:9 的结构契约必须同时约束事实来源

- 日期：2026-07-31
- 决策：content:9 的复盘输出不得在任务材料和已验证网页都没有依据时给出具体百分比、权重、行业基准或阈值；这些内容命中即判定契约无效。允许“待补历史基线”“由负责人设定”等明确披露数据缺口的表述，也允许复用任务或已验证网页中可追溯的事实。
- 原因：结构完整、字段齐全的复盘文本仍可能编造“完播率目标”“收藏权重”等精确数字；如果只校验 JSON 形状，会把不可证实的管理指标送入人工审批甚至“可使用”链路。
- 影响：事实门禁失败会把原任务与具体错误交给一次真实模型修复重试；模板、fallback、失败或仍无来源的结果都不能升级为成功。正反例已进入最新 `696/696` 服务端回归，类型、隔离、token、UI 契约、严格 lint、格式和生产构建同时通过。该工程证据与真实云浏览器复跑、人工内容审阅分别留证。

## D-048｜技术完成、账务完成、质量完成和业务可用必须分层

- 日期：2026-07-31
- 决策：任何真实 AI 产物都不能只凭供应商返回或数据库有正文进入“待审阅/可使用”。审阅资格必须同时满足真实 API、正 token、有效契约、持久化成功、无内部档案泄漏和已结算账务；账务缺失或不一致统一进入“待账务对账”，并禁用审阅、预览、下载、入库与发布。
- 原因：内容员工、自动内容、媒体任务、工具箱和驾驶舱过去各自推导状态，造成“生成完就像可用”“未结算却能审阅”等跨页矛盾。
- 影响：内容仓、任务中心、媒体卡片、工具箱、业务流和驾驶舱使用同一权威语义；自动质检通过与人工采纳继续分开表达，外部发布永不由内部可用状态自动触发。

## D-049｜历史失败必须保留，修复以同场景真实复跑闭环

- 日期：2026-07-31
- 决策：失败、驳回、释放和非法输出不删除；每次升级以相同业务规则重新调用真实云 API，并保存供应商模式、模型、token、finish reason、契约、计费、审批和下游副作用。
- 原因：删除失败或只跑单元测试无法说明原问题已经关闭，也会掩盖人工驳回与系统门禁分别发现的问题。
- 影响：复盘官运行 #7/#8 保留人工驳回，#9 保留安全失败，#10 真实复跑通过后由老板审批；只有 #10 创建内容资产和知识库，四次运行均无外部发布。
