# 决策记录

## D-001｜密钥只做进程级临时注入

- 日期：2026-07-30
- 决策：不通过管理后台保存密钥，不创建 `server/.env`，只给本次服务进程注入。
- 原因：当前后台保存会把完整密钥以明文写入 SQLite；界面掩码仅是回显掩码，不是加密存储。
- 结果：工作树、原演示库和隔离测试库的 `sys_config` 均无云雾密钥记录。

## D-002｜真实测试使用隔离数据库

- 日期：2026-07-30

- 原因：演示库存在启用且到期的内容自动化，启动真实通道会立即执行并产生费用与业务数据。
- 结果：原演示库回到测试前基线；隔离测试库关闭全部自动化后用于页面验收。

## D-003｜只保留一次真实推理调用

## 修复后迭代结果（决策）

> D-001 至 D-013 为修复前基线与本轮开工决策，继续保留；以下决策记录实现与发布收口后的当前口径。

## D-014｜联网检索必须在预授权之后执行

- 日期：2026-07-30
- 决策：`webRequired` 岗位先完成权限、余额预检和可追踪占扣，再调用检索服务；没有可引用证据即停止，不调用生成模型。
- 原因：检索本身属于外部成本，不能在余额检查前调用，也不能用模型记忆冒充实时证据。
- 影响：内容员工手动、立即和定时路径均保留检索供应商、来源标题、URL、摘要和失败原因快照。

## D-015｜后台 AI 并发租约保持到真实终态

- 日期：2026-07-30
- 决策：所有响应后继续运行的后台 AI 任务必须调用 `req.aiGuard.defer()`，并在成功、失败或异常终态的 `finally` 中释放。
- 原因：HTTP 响应完成不等于上游任务完成；提前释放会让并发保护失真。
- 影响：内容后台生成和内容员工后台派活均有生命周期回归测试。

## D-016｜业务产物先落库再结算

- 日期：2026-07-30
- 决策：内容员工运行必须先可靠落库完整产物与待结算快照，再结算占扣；落库失败全额释放，结算失败保留产物并标记 `pending_reconciliation`。
- 原因：禁止出现“积分已扣但业务交付不存在”。
- 影响：成功、落库失败、结算失败三条路径都有独立自动化证据。

## D-017｜采用三级发布结论

- 日期：2026-07-30
- 决策：本地无密钥演示 **GO**；自动化本地回归 **GO**；生产 **CONDITIONAL GO**。
- 原因：本轮定义的本地代码层 P0/P1 发布阻断已全部关闭；生产仍未使用轮换后的授权凭证执行真实云雾、支付、飞书和外部发布链路。
- 影响：不得把本地自动化通过表述为真实生产渠道已验收；满足外部复验条件后才能放量。
- 证据：最终自动化测试 `456/456` 通过，0 失败。

## D-019｜固定模板不得冒充实时 AI

- 日期：2026-07-30
- 决策：内容生产仓固定模板只能标记为参考或草稿，不得表述为实时 AI 生成、实时扫描结果或真实经营数据。
- 原因：预置内容用于引导和演示，不具备实时模型调用与实时数据来源证据。
- 影响：模板仍可辅助用户起步，但不能进入真实 AI 产出、实时情报或经营成效口径。

## D-020｜内容自动化采用可追踪异步契约

- 日期：2026-07-30
- 决策：立即执行返回 `202 + runId + pollUrl`，客户端按 `runId` 精确轮询；同一次运行幂等复用，手动与定时领取统一执行租户、员工和 `content` 模块撤权门禁，费用估算、占扣与生成使用同一实际模型。
- 原因：HTTP 接单不等于任务完成，且授权或模型口径在排队期间漂移会导致越权、重复执行或计费不一致。
- 影响：内容自动化具备稳定终态、重复提交保护、执行时授权复核和一致的成本证据。

## D-021｜支付结果必须唯一、绑定且新鲜

- 日期：2026-07-30
- 决策：支付报文拒绝重复关键节点，渠道结果必须绑定当前本地商户订单；微信签名响应只接受五分钟内的时间戳。
- 原因：重复字段、订单错绑和陈旧签名响应都可能把攻击或其他订单结果误判为当前交易成功。
- 影响：支付状态机在自动化层具备节点唯一性、订单关联性和响应新鲜度证据；真实渠道仍须沙箱/生产验收。

## D-022｜RAG 后台任务使用完整成本与生命周期保护

- 日期：2026-07-30
- 决策：RAG 后台任务在执行前预授权，按真实用量结算，与其他 AI 路径共享并发额度；超时必须释放资源，服务重启后恢复可恢复任务。
- 原因：后台响应结束不代表计算结束，独立并发池、估算即结算或无恢复机制都会造成超卖、悬挂占扣和孤儿任务。
- 影响：RAG 的计费、并发、超时和重启路径均进入自动化回归；本轮本地代码 P0/P1 发布阻断据此关闭。

## D-023｜技能验证分层，不把目录验证冒充效果验证

- 日期：2026-07-30
- 决策：409 项历史技能逐项补齐来源快照、岗位、版本、内容指纹和离线验收样本；通过后状态只表示“目录与执行注入契约已验证”，真实业务效果仍需带凭证的线上样本验收。
- 原因：来源完整性、结构可执行性和业务效果是三类不同证据，不能用一次离线测试替代真实平台效果。
- 影响：前后端统一展示验证层级和证据，不再用笼统的 `legacy_unverified`，也不声称算法规则或平台表现已经实时验证。

## D-024｜连接器状态必须对应真实运行能力

- 日期：2026-07-30
- 决策：代码盘点确认实际有 8 个 `catalog_only` 连接器（旧报告计数为 7）；8 个必须全部进入统一运行登记。本地可执行的标记为本地可运行，需要外部授权的标记为“未启用/需要凭证”，并在调用边界拒绝冒充成功。
- 原因：目录条目不是连接成功，用户必须能区分可运行、待授权和不可用。
- 影响：内容员工档案、执行快照和接口返回同一状态；本轮不调用真实平台、不自动发布。

## D-025｜餐饮岗位产出由严格机器契约验收

- 日期：2026-07-30
- 决策：60 名餐饮员工均提供岗位级严格 JSON Schema 和机器校验器；契约由岗位真实交付物派生，企业追加提示词不能降低必填项、类型、非空、数量或未知字段限制。
- 原因：只有提示词和人工风险扫描无法证明完整岗位能力已经交付。
- 影响：岗位档案、派活执行、产出采纳和测试共享同一契约；所有结果仍需按岗位审批边界人工终审。

## D-028｜“已配置”与“已验证连接”是两种状态

- 日期：2026-07-31
- 决策：运行就绪状态采用多维事实；只有实现完整、配置完整、已启用且存在与当前配置匹配的新鲜显式成功验证时，才允许使用“已连接”。
- 原因：API Key 或字段存在只能证明配置存在，不能证明网络、鉴权、模型、证书、接收人或外部动作可用。
- 影响：就绪 GET 严禁联网；后台与系统页统一显示 `configured_unverified / connected / blocked / manual_only / disabled` 等真实状态。

## D-029｜占扣终态只信任数据库权威记录

- 日期：2026-07-31
- 决策：结算和释放必须在事务内按 hold ID 回读权威租户、流水和金额，调用方快照只用于一致性校验，不能作为更新依据；恢复不得因租户停用或单条坏记录跳过其他开放工作。
- 原因：恢复输入可能陈旧或被错误拼装，直接信任会扩大为跨租户或错金额账本风险。
- 影响：加入双租户伪造、重复终态、停用租户和故障隔离回归；持久化人工对账、视频主动轮询和请求级幂等仍作为后续独立切片。
