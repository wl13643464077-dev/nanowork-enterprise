## 70 位完整数字员工

- [ ] 当前目录为 60 位餐饮员工（8 个专业分部、编号 101—160）与 10 位 Paihuo 内容员工（编号 0—9），合计 70 位。
- [ ] 70 位员工均可打开“单独派活、能力、工作方式、技能库、提示词、工作配置、岗位档案”七个面板。
- [ ] 每位员工都有与岗位职责匹配的问题示例、输入标签、资料清单和交付检查项；不存在把同一通用问题套给不同岗位的情况。
- [ ] 每次执行都注入岗位身份、锁定能力、工作方式、岗位提示词、当前配置、出厂 Skill、启用技能和人工审批边界。
- [ ] 出厂核心能力与岗位 Skill 锁定启用；企业补充提示词、自定义技能和配置只能追加，不能替换或削弱岗位合同。
- [ ] 安全白名单技能快照覆盖 70 位员工与 409 张历史技能卡，且历史技能标注 `legacy_unverified`，不冒充已核验事实。
- [ ] 普通账号只能看到掩码后的完整提示词信息，但服务端执行仍使用完整岗位提示词，并保存可核验的岗位修订与提示词哈希。

## 文件与证据输入

- [ ] 餐饮和内容员工派活均可从统一文件中心选择最多 6 个附件。
- [ ] 服务端验证文件 ID、企业归属、用户权限和数量上限；跨企业文件、无权限文件、无效 ID 与超量请求会被拒绝。
- [ ] 可读取附件的正文以“不可信资料”边界注入模型；不可读取文件只保留引用信息，不伪装成已经识别。
- [ ] 任务快照只保存文件引用、名称、类型、大小与哈希等安全元数据，不复制原始文件正文。
- [ ] 另可附 1 张 PNG、JPEG 或 WebP 内联图片；原图只随本次模型调用使用，快照不保存原始 data URL。

## 内容生产仓

- [ ] 内容生产仓展示趋势官、情报员、拆解师、撰稿人、文风师、多媒体师、封面师、演绎师、分发官和复盘官 10 位正式员工。
- [ ] `quality_gate` 是审查服务，不占员工编号，不计为第 11 位内容员工。
- [ ] 10 位员工均执行岗位专属 JSON 输出契约；缺字段、字段类型错误、危险内容或不符合岗位结构的结果会被标记为契约失败。
- [ ] 契约失败的内容不能采纳，只能驳回或修复；演绎师的主交付为完整、安全的 HTML，PPT 仅为附加连接器。
- [ ] 趋势官、情报员和拆解师在要求实时证据时执行真实联网检索，保存检索状态与来源；失败时明确列出待核验项。
- [ ] 撰稿人、多媒体师和演绎师的专用连接器执行其完整岗位身份、能力、提示词、配置、技能与输出契约，不只是挂员工名称。
- [ ] 人工采纳内容员工结果时，以 `content_employee_run` 来源幂等写入素材库，并保留运行引用；驳回不写入素材库。

## 手动、自动与定时任务

- [ ] 支持手动创作、立即自动执行、每日定时和每周定时，计划时间按 `Asia/Shanghai` 计算。
- [ ] 每位内容员工只接受自身允许的三类岗位任务；创建、编辑、启用和手动运行都会在服务端再次校验匹配关系。
- [ ] 自动任务按规则与风险进入“待审核”或“可使用”；“可使用”不等于已发布，系统不自动写入素材库、不连接外部账号，也不自动发布。
- [ ] 并发调度使用事务原子认领和唯一认领键；同一计划时间不会产生重复运行。
- [ ] 服务启动和轮询会恢复超过安全时限仍处于“运行中”的任务，将其标记失败并记录原因；较旧运行不会覆盖较新运行状态。
- [ ] 规则运行历史保留触发方式、计划时间、状态、错误与结果引用，便于审计。

## 审核、素材与发布边界

- [ ] 内容员工单独派活必须通过人工审阅才能采纳；其他内容按风险和规则进入“待审核”或“可使用”。待审核、驳回、生成失败和输出契约失败的内容不能进入发布登记。
- [ ] 审核通过或采纳操作保持幂等，不会重复创建素材；结果进入素材库后仍不代表已经发布。
- [ ] 图片、视频和演示附件只有在生成成功、类型正确、具有有效地址且由管理角色完成人工验收后才允许导入；技术生成成功不能冒充业务可用。
- [ ] 发布由授权人员在外部完成后人工登记渠道、浏览量和线索数；效果登记不会触发平台自动发布。
- [ ] 分发官只交付多平台适配稿与终审清单，不登录第三方平台，不代表企业作外部承诺。
- [ ] 文案、后台生成、PPT、图片、日更包、立即自动与定时自动均执行“预授权 → 业务事务落库 → 结算”；未交付全额退回，结算异常标记待对账且不冒充实扣。

## 权限、数据与账号

- [ ] 老板驾驶舱只向有管理权限的角色展示企业全量指标；普通角色的趋势、漏斗、健康度与明细不会回退到全企业数据。
- [ ] 内容、素材、文件、自动规则、运行历史、员工任务与分析详情均受企业和用户范围约束。
- [ ] 账号“停用”采用软停用：保留用户 ID、历史内容、任务、审批与运行归属，并同步关闭该用户仍启用的内容自动任务。
- [ ] 当前登录账号、平台超级管理员和企业最后一个启用的老板/管理员不可被停用；重复停用保持幂等。
- [ ] 重新启用账号不会自动恢复此前被关闭的自动任务，必须由有权限人员逐条确认。
- [ ] 价格、库存、食安、财务、法律、隐私、收益与顾客评价相关结论均要求事实依据和人工确认。
