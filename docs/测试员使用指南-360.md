# 纳米 Work 测试员使用教程

2026 年 9 月 14 日更新 · 完整产品测试员版 · 360 智脑主用 · 自定义体验次数

这份教程适用于测试员、销售伙伴，以及负责审核的 Super 管理员。按「申请账号 → 登录完整产品 → 右上角测试员后台绑定 360 Key → 数字员工派活 → 任务中心查看结果 → 发体验二维码 → 审核与跟进客户」完成第一次使用。

**本轮统一使用 360 智脑。OpenLux 保留为备用入口，先不用切换。** 360 Key 是你在 360 创建的调用凭证，不是纳米 Work 的登录密码。

## 1. 申请测试员账号，等待审核

1. 打开测试员申请页，填写本人姓名、所属部门／团队和 11 位手机号。部门填写公司统一名称，例如「成都销售一部」「渠道合作团队」；填错时联系 Super 校正。
2. 设置登录账号：使用 4-32 位字母、数字或下划线，例如 `zhangsan01`。设置至少 8 位密码。
3. 阅读申请与使用记录说明，勾选同意后点击「提交申请」。
4. 等待平台审核。显示「申请已提交」表示申请已收到，不等于已经开通。
5. 审核通过后，用刚才设置的账号和密码登录，默认进入完整产品主页。左侧保留数字员工、任务中心、内容生产仓等业务入口；右上角显示「测试员后台」，身份为「测试员」。

测试员账号仅供本人使用，不能创建子账号，也没有企业充值、系统管理或平台管理权限。个人 Key、体验码与客户看板统一在右上角「测试员后台」。客户通过你生成的体验二维码使用自己的体验入口，无需获得你的账号或 Key。

## 2. 在 360 申请自己的 API Key

1. 打开 360 官方登录页，按页面提示注册或登录自己的账号。
2. 进入「API Key」管理页面，创建 Key，并复制完整内容。不要额外复制引号、空格或换行。
3. 核对 Key 所属组织和账户可用额度；如当前账户没有可用额度，按 360 控制台提示充值或开通。

360 官方快速开始说明了 API Key 的申请入口及保密要求；遇到官方界面变化可先查看 [360 快速开始](https://ai.360.com/docs/quick-start)。不要将完整 Key 发到群聊、客户聊天或截图中。发生泄露时，在 360 撤销旧 Key、创建新 Key，再回纳米 Work 更新。

## 3. 把 360 Key 填到纳米 Work

1. 登录完整产品，点击右上角「测试员后台」→「供应商与个人 Key」。也可直接打开 [个人 Key 设置](https://纳米work.cn/tester?tab=key)。
2. 新开通的测试员默认选择「360 智脑」。已有账号请确认当前选择；如果看到 OpenLux 被选中，先点「360 智脑」。
3. 在「360 智脑 API Key」输入框粘贴完整 Key，点击「保存 Key」。
4. 保存后，页面应显示已绑定状态和隐藏部分字符的 Key。
5. 点击「去数字员工」或左侧「餐饮数字员工」，选择岗位，发起一条简单需求；到该员工工作面板或「任务中心」确认实际结果。

**保存成功只表示 Key 已保存。收到数字员工的实际回复，才表示这次连接可用。** 若需更换 Key，在相同页面粘贴新 Key 后再次保存。修改登录密码可从头像菜单进入，或打开「测试员后台」→「修改密码」。

本人使用和二维码客户调用都使用你的个人 Key，纳米 Work 不重复扣减测试员的平台算力余额。完整 Key 不会展示给客户。

## 4. 在完整产品派活，到任务中心看结果

测试员与企业用户使用同一套业务页面。点击左侧「餐饮数字员工」，按经营问题、岗位或部门找到员工；进入该员工的正式工作面板后，参考自我介绍和「一句话使用我」示例，描述门店资料、目标和希望交付的内容。需要图片或其他材料的任务，在对应面板按实际要求上传。

可以从下面三个需求开始：

- **巡店：**「我有一家 12 张桌子的火锅店，今天检查发现迎宾交接漏项、冷藏标签不清。帮我整理问题、整改负责人和复查安排。」
- **小红书种草：**「我经营一家成都火锅店，主打鲜切牛肉和手打虾滑。用我上传的品牌与菜品照片，做一组朋友聚餐风格的 6 图种草内容，不编价格和优惠。」
- **视频带货：**「用我上传的门头和菜品照片，做 15 秒火锅带货视频，主题是下班约朋友聚餐，口播自然，先说明脚本与生成方案。」

**本人正式业务与客户扫码体验分开。** 本人可进入数字员工、内容生产仓及其他已开放业务页面，使用自己的个人 API Key；图片、视频在对应正式创作流程中按界面要求生成。可用能力以供应商和当前页面为准。数字人摄影棚需要单独配置服务，当前个人 API 模式暂不支持。客户 H5 仍是五个岗位，但这五位按正式岗位完整能力执行：选址含调研和竞品核验，店长和巡店出完整报告，小红书和带货按完整岗位方案交付。没有照片或素材时，先给完整文案与制作清单，不假装文件已经生成。

提交任务后，到左侧「任务中心」查看执行状态；有结果时打开详情，查看原始输入、正文、图片或视频等实际交付。根据任务提供的按钮预览、下载、复制或反馈。等待较久时先刷新原任务，避免重复派活。本人正式任务不占任何客户的体验次数。

**旧版记录在哪里：**「测试员后台」→「历史文字测试」只读保留旧版文字测试最近 100 条输入与结果，可展开、复制。这里不再提供员工选择或发送按钮；新任务历史统一在「任务中心」。客户记录仍在「测试员后台」→「客户与使用记录」。

## 5. 生成你的客户体验二维码

客户扫码后固定展示以下五个入口，按这个顺序排列。这五位都是满血岗位，不是精简问答：

| 入口 | 可以怎样体验 |
|---|---|
| 选址 | 按正式选址岗位调研铺位、竞品、客流和租金压力 |
| 超级店长 | 按正式店长岗位判断活动是否适合，给出执行方案，并生成配套物料图 |
| 巡店 | 按正式巡店岗位整理评分、问题清单和整改安排 |
| 小红书种草 | 按正式种草员写标题、正文、标签、首评及配图方案 |
| AI带货 | 按正式带货员写口播、分镜及成片方案 |

**新旧二维码都使用这五个满血入口，无需重新生成二维码。** 旧对话仍可查看；不在这五项内的岗位不再接受新的客户体验请求。测试员本人通过完整产品的「餐饮数字员工」等业务入口使用其余正式岗位。

1. 再确认当前供应商是「360 智脑」，且个人 Key 已绑定。
2. 打开「测试员后台」→「体验二维码」，填写「邀请名称」「销售手机号」和「每位客户体验次数」。次数支持 1-100 的整数，默认 2 次。例如邀请名称可写「张三 · 餐饮老板体验」，手机号填写你自己的联系方式。
3. 点击「生成体验二维码」。
4. 点击「预览 H5」检查标题、每位客户的体验次数、销售联系方式和供应商。
5. 点击「下载二维码」保存图片，或点击「复制链接」，发给客户。

**对外分享时，应在正式网站生成，预览地址应以 `https://纳米work.cn/try/` 开头。** `localhost`、`127.0.0.1` 是本机地址，手机和客户通常无法访问，不能作为公开体验码。发现这种地址时，请管理员检查正式网站的公开体验地址配置，然后在正式网站重新生成。

每个二维码固定绑定创建时的测试员和供应商。之后切换供应商不会改变旧二维码；旧码不会自动改用备用通道或平台 Key。客户的 API 费用计入该销售测试员在对应供应商的个人账户。

**次数是每位客户独立享有的总额度，由五个数字员工共用。** 例如设置为 5，每位通过审核的客户都可成功体验 5 次，不是整张码只有 5 次，也不是每个员工各 5 次。创建时确定本码额度，客户申请时保存自己的额度；已有二维码和客户保持各自原额度，更早的旧记录默认 2 次，不追溯修改。本次支持创建时设置，不提供修改已生成二维码额度的按钮。

## 6. 客户扫码后，你要做什么

1. 客户扫码打开 H5，阅读介绍，填写称呼、手机号及可选的门店名称，同意体验记录说明后提交申请。
2. 你在「测试员后台」→「客户与使用记录」找到该客户，点击「同意体验」。Super 管理员也可以审核。
3. 客户等待页会更新审核状态。通过后，客户选择岗位、输入需求，在剩余额度内继续体验。
4. 每位获批客户在这五个岗位之间共用本码设定的成功次数，页面显示已使用、总额度和剩余次数。选择或切换岗位不扣次数，也不会补回次数；失败且没有可用结果时可以重试。
5. 次数用完后，客户仍可查看已有输入输出，并通过页面上的销售手机号联系你。

刷新页面、重新打开同一个入口不会补回已用次数。恢复已暂停的客户也不会重置次数。同一客户手机号全局只能领取一次体验资格，换用其他销售的二维码也不会重置额度。客户手机号、门店、主动选过的岗位、使用次数及对话内容会按体验说明提供给邀请人和 Super；请客户只提交本次体验需要的经营信息。

## 7. 看客户用了什么、花了多少

打开「测试员后台」默认进入「客户看板」，可选近 7 天、30 天、90 天或全部时间。

| 想了解什么 | 在哪里看 |
| --- | --- |
| 申请了多少人、用了多少人、还有多少未用 | 看板顶部客户指标 |
| 哪些客户等待审核、哪些已经用完设定次数 | 「客户与使用记录」中的状态、已使用次数和个人总额度 |
| 客户实际用过哪些数字员工 | 看板中的功能使用情况 |
| 调用了哪些模型、成功与失败次数 | 看板中的模型维度 |
| 哪天邀请和使用比较多 | 看板中的每日趋势 |
| 客户主动选了什么、成功用了什么 | 「客户关注的功能」中的选择人数与使用人数 |
| 客户具体输入和最终结果 | 客户列表 →「输入与结果」 |
| 实际消耗了多少钱 | 已核实供应商成本、待核实调用次数及逐条记录 |

「主动选过」表示客户在页面选择过该岗位，不能当作购买意向。看板只统计客户。本人正式业务历史在「任务中心」；旧文字测试记录和成本在「测试员后台」→「历史文字测试」，不混入客户指标。

客户数量按所选时间内的申请统计；调用和费用按实际发生时间统计。因此本期费用中可能包括更早申请、近期才来使用的客户。

## 8. 费用与余额怎么核对

测试员本人发起的正式新任务使用当前选择的个人供应商 Key；已有持久任务的重试按原任务供应商继续使用本人 Key。关联客户使用二维码创建时绑定的供应商 Key。费用由对应供应商直接记入测试员的个人账户。**测试员个人 Key 模式不按平台销售价再扣一次费用。**

记录有可核实的人民币消耗回执时，工作台展示该实际金额；供应商未返回可核实金额时，显示「待供应商核实」，不把未知金额当作零元。可前往 [360 用量与账单](https://ai.360.com/open/zh/platform/account/usage) 核对。

调用失败也可能已产生供应商费用。已知金额会保留在调用记录中；同一份可识别的扣款回执不会重复累计。客户体验次数只在成功交付回复后消耗，上游计费与客户体验次数是两个不同的记录。

正式企业账号使用平台 Key 和算力余额，属于企业产品的定价与结算流程。不要用企业销售价格推算测试员个人 Key 的费用。

## 9. 停止体验与 Super 管理

- 暂停某一位客户：进入「客户与使用记录」，点击该客户的「暂停」；需要时可「恢复」。
- 停用某一个二维码：进入「体验二维码」，点击该邀请的「停用」。
- 暂停整个测试员账号：Super 进入「测试员与体验」，对该账号点击「立即叫停」。该测试员及关联客户将不能继续发起新生成，历史记录保留。
- 查看全部销售效果：Super 在「销售邀请与客户体验看板」按销售筛选，并查看邀请、客户申请、模型和详细输入输出。

已提交给供应商的请求可能已经产生费用，暂停账号不会撤销供应商账单。

## 10. 常见问题，按这个顺序处理

| 现象 | 先做什么 |
| --- | --- |
| 申请后无法登录 | 联系管理员确认审核已通过，核对自己设置的账号和密码 |
| 提示先绑定 Key / 按钮不能点 | 到「测试员后台」→「供应商与个人 Key」选择 360，保存自己的有效 Key |
| Key 保存成功，聊天仍失败 | 核对完整 Key、组织和 360 余额；保留报错及调用时间，不要提供完整 Key |
| 提示模型或参数错误 | 将报错与时间发给管理员核查；仅凭 1001 不能判定账号没有权限 |
| 客户一直等待审核 | 到「客户与使用记录」点「同意体验」，让客户刷新状态 |
| 手机扫码打不开 | 检查是否为正式域名，排除 localhost / 127.0.0.1；再检查邀请是否停用 |
| 入口以前能用，现在不可用 | 检查测试员、客户、邀请的状态，以及绑定的 360 Key 是否被删除或失效 |
| 结果已经出现，费用仍待核实 | 先保留结果，按调用时间核对 360 账单；不要为获取费用重复生成 |
| 看板数字没有马上变化 | 点击「刷新看板」或「刷新记录」，并检查所选时间范围 |

## 第一次给客户发码前的自检

确认账号已审核、选中 360、Key 已绑定、本人已收到一次真实回复、预览 H5 使用正式域名、销售手机号正确。随后发码，客户申请后及时审核，最后到看板确认客户的成功次数和输入输出有记录。

## 本教程的范围

本教程于 2026 年 9 月 18 日更新为客户体验码五个岗位使用满血能力；自定义次数规则保留。操作教程与测试验收结论分开；实际测试结果以对应复测报告为准。360 控制台界面可能更新，创建 Key 的入口及要求以官方当前页面为准。

## 管理员补充：按部门管理测试员与体验效果

1. 进入「平台运营后台 → 测试员与体验 → 测试员」，核对申请人所属部门／团队。旧账号显示「未分类」。
2. 点「调整部门」，选择已有名称或填写统一名称，点「保存分类」。留空保存归为未分类。仅 Super 可调整，并保留审计记录。
3. 顶部部门筛选联动测试员、客户和邀请二维码名单；清空后查看全部。
4. 到「销售与客户看板 → 部门效果」，按时间比较各部门测试员／已开通人数、客户数、已用／未用人数、已体验率、成功问答、调用／失败次数与已核实成本。再按部门和销售筛选，查看具体使用功能、模型与关注点。
5. 分类以测试员当前所属部门为准；调整后历史客户及调用一起归入新分类，不改变原邀请人、账号权限、个人 Key 或客户体验次数。已体验率不代表付费成交率，未知成本仍待核实，不能当免费。

以上为本地新版功能；上线状态以发布记录为准。

## 入口更新：完整产品与测试员后台

默认登录仍进入完整产品主页；右上角「测试员后台」进入独立后台，左侧业务导航不再放体验管理。后台集中查看已生成的体验码、客户记录、使用看板、个人 Key；点「返回产品首页」回到经营工作台，或点「去数字员工」直接派活。手机产品页右上角也有相同入口。旧的 /tester 及其 tab 链接继续可用。
