## 0. 定位与边界

- 目标：一台干净的 Ubuntu 22.04/24.04 云主机，**30 分钟内**跑起可公网访问的演示环境（临时域名 + HTTPS + 6 家演示企业账号）。
- 这是**演示环境**，不是 `docs/team/04-decisions.md` D-078 所指的"公网生产放量"。D-078 的 HOLD 条件（服务器、域名、TLS、数据迁移、备份恢复、登录/SSE/下载验收）本清单逐条落实，但支付、飞书、外部发布等不可逆链路仍按 `docs/team/11-release.md` 保持 fail-closed。
- 与 `docs/team/11-release.md`「生产发布前置清单」的对应关系用 **[11-R#n]** 标注（n 为该清单第 n 个复选框，从 1 起算）：
  - [11-R1] 轮换已暴露的云雾密钥 → T-5
  - [11-R2] 新密钥完成文本生成与联网检索验收 → T-3 就绪矩阵
  - [11-R3] 支付沙箱验收 → **本次不做**，支付保持留空（对公转账流程）
  - [11-R4] 飞书验收 → **本次不做**，飞书留空
  - [11-R5] 外部发布验收 → **本次不做**，保持"人工登记"
  - [11-R6] 无明文密钥/悬挂 hold/孤儿任务 → T-2 检查
  - [11-R12] 发布负责人复核环境变量、备份、回滚、责任人 → T-2/T-1
- 桌面端（`docs/team/desktop-clients/10-release.md`「服务器和域名接入」）要求：Web 与 API 同一 HTTPS origin、`/api/health`、登录 Cookie、SSE、SPA fallback、受保护下载实测通过、不允许忽略证书错误。本清单 T-3 步骤 8 覆盖。

1. **uploads 目录不可配置**：`server/src/app.js`、`engines/filehub.js`、`engines/wechat-draft.js` 等写死 `server/data/uploads`；本次用符号链接 `server/data -> /var/lib/nanowork/data` 解决。建议后续增加 `NANOWORK_DATA_DIR` 环境变量统一 `db.js` 的 `DATA_DIR`。
2. **`index.js` 没有 `--check` 只读模式**：自检由独立的 `scripts/preflight-production.mjs` 完成；若后续想让 `node src/index.js --check` 直接复用启动逻辑，需要把 `initSchema/migrate` 与 `listen` 拆开。
3. **就绪矩阵接口**：`/api/admin/runtime-readiness` 只允许 `boss/admin`，`platform_super` 会 403；deploy.sh 改用 `/api/sys/runtime-readiness`（允许 `platform_super`）。文档若写前者请注意。
4. **注册限流含成功计数**（`routes/auth.js` `recordFailure(registerAttempts, ...)` 对成功注册也计数）：批量建租户必须临时提高 `REGISTER_IP_MAX_ATTEMPTS`。可考虑对 `platform_super` 提供"平台直接开通企业"接口，省掉公开注册 + 审批两步。
5. **高德 Key（批次 A8 已接入）**：`engines/amap.js` 读取 `AMAP_WEB_KEY`/`AMAP_BASE_URL`，选址岗位 101/102/104 高德优先、失败回落 OSM（Overpass/Valhalla，国内公共实例可能慢）。就绪矩阵第 9 通道 `amap`；管理后台 → 接口管理 有"测试连接"卡；`preflight-production.mjs` 未配置只 WARN。
6. **`fonts-noto-cjk` 与代码探测路径不匹配**：Ubuntu 包只有 `.ttc`，`skillrun.js`/`docx-report-renderer.js` 拒绝 TTC，因此 install 脚本额外下载单文件 OTF 到 `/usr/local/share/fonts/NotoSansCJK-Regular.otf`（已在探测列表中）。
7. **`scripts/migrate.mjs` 默认快照目录在代码目录 `backups/`**，只读文件系统下会失败；生产 env 必须设 `MIGRATE_SNAPSHOT_DIR`（模板已给）。
8. **登录/注册限流是进程内存态**：`systemctl restart` 即清零；多实例部署时不共享。演示单机无影响。
