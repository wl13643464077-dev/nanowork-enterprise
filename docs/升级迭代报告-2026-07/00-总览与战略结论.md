## 一、一句话诊断

**这不是"实习生写得漏洞百出"，而是"工程能力用错了地方"。**

底层工程质量明显高于平均水平：两阶段预授权计费（6 个专项测试）、多租户三层隔离机制（AsyncLocalStorage + scoped 查询 + INSERT 自动注入）、调度器原子认领与重启恢复、scrypt 密码哈希、HttpOnly Cookie + jti 会话吊销、统一错误处理带 requestId、SSE 流式基建、17 个路由 lazy 分割、ECharts 按需注册——这些都是真实且正确的。

但三个致命的结构性问题让产品在客户面前立不住：

1. **表现层完全失控**：没有设计系统，19,282 行前端里散落 777 处硬编码颜色（226 个唯一色值、品牌蓝 11 个变体）、2,044 处内联 style、37KB CSS 塞在 5 个 JS 模板字符串里。UI 成熟度 **3.4/10**。
2. **业务数据模型不是餐饮的**：74 张表里，**0 张**门店表、菜品表、SKU 表、库存表、排班表、会员储值表、订单明细表、成本表。`orders` 是"一单一菜一金额"的单行结构，`product` 是自由文本。行业适配度 **3.0/10**。
3. **一批"画了但没通"的假功能**：8 个经营工具零 AI 调用（纯字符串模板）、餐饮员工派活主入口前端 0 调用、AI 音频是纯装饰 Tab、充值无支付通道、登录页展示编造的"今日营业额 ¥18,642 / 午市翻台率 2.34"。321 个接口里 **51 个（15.9%）** 前端从未调用。

## 三、与竞品的真实差距

| 能力 | 客如云五大智能体 | 美团智能掌柜 | 百度一见 AI 数字店长 | 纳米Work 现状 |
|---|---|---|---|---|
| 经营数据来源 | 自有收银 + 抖音/高德/美团/淘宝闪购接入 | 美团平台全量真实交易与评价数据 | 门店摄像头视觉流 | ❌ **仅人工 Excel 导入** |
| 多门店 / 连锁总部 | ✅ 连锁管控 + 远程接管 | ✅ 品牌驾驶舱，一键全店报表 | ✅ 3 万门店全量接入 | ❌ 隔离粒度只有 tenant |
| 选址 | ✅ 智能选址大数据 | ✅ 预测近 30 天日均到店客流 | — | ❌ 无 |
| 菜品 / 库存 / 排班 | ✅ 全链路 | 部分 | ✅ 物料盘点分钟级 | ❌ 数据模型不存在 |
| 团购券核销 | ✅ 抖音 + 美团双平台统一核销 | ✅ 原生 | — | ❌ 无 |
| AI 智能体数量 | 5 个（管理/营销/门店/运维/服务） | 单店版 + 品牌顾问 | 1 个数字店长 | 70 个（但为同一执行器 + 70 条 JSON 人格） |
| 已验证规模 | 点都德、西塔老太太（百万级会员） | **70.8 万商家**，660 万经营困惑，16 万份报表，省 65% 人工 | 咖啡品牌 3 万门店，准确率 80%→95% | 无公开客户数据 |

**结论**：竞品在"数据管道 + 平台生态"上建立了纳米Work短期无法追平的壁垒。纳米Work唯一可能的差异化在于**跨岗位的深度 AI 交付物 + 可审计的人机协同治理**——这恰好是国际 AI Workforce 平台（ServiceNow AI Control Tower、Atomicwork、SICKR.ai、BotWorks ARP）在 2026 年定义的新品类，而项目已有的「两阶段计费 + prompt 哈希快照 + 审批边界 + 产出溯源」正是这个品类的核心资产。

详见 `01-竞品基准与市场定位.md`。

## 四、三条战略路线（必须先选一条）

### 路线 A：收缩定位——「餐饮内容与营销 AI 工作台」（推荐）

**做法**：放弃"门店经营工作台"这个正面对撞客如云/美团的定位，收缩到自己真正做扎实的地方——内容生产（content 模块 3,240 行 + 10 位内容员工 + 严格 JSON 输出契约）、营销活动闭环（26 个接口全闭环 + AI 复盘回知识库）、会员线索 CRM（20 个接口全闭环）。

- 优势：这三块现在评分 7-9，是真能力，不用重写数据模型
- 需要做的：删掉/收敛所有做不到的宣称，UI 全面升级，工具箱补真 AI
- 定位话术：不做收银替代，做「客如云/美团之上的 AI 内容与营销中台」，通过抖音/美团开放平台读数据，不碰交易

### 路线 B：正面补齐——「真门店经营工作台」

**做法**：补 8 类核心数据表 + 接入抖音生活服务 OpenAPI + 美团开放平台 + 至少一家 POS。

- 代价：数据模型重构 4-8 周，每个平台对接需资质与商家授权链路，抖音需服务商认证
- 风险：进入客如云（软硬一体 + 生态流量）与美团（平台数据独占）的主场，功能对比处于全面劣势

### 路线 C：转向治理层——「AI 数字员工治理平台」

**做法**：把 70 岗目录 + 技能库 + 两阶段计费 + 审批边界 + 产出溯源，重新包装为国际市场正在成型的 AI Workforce Governance 品类（身份/权限/技能/预算/绩效/生命周期/治理/协作 八维度），支持 MCP 接入外部智能体。

- 优势：现有工程资产复用率最高（计费、审批、溯源、隔离全部可直接用）
- 代价：目标客户从"餐饮门店老板"变为"中型企业 IT/运营负责人"，销售路径完全重构

**建议**：**先执行路线 A 的全部内容（这是止损与立信的必要动作，无论最终走哪条路都必须做），同期把路线 C 的治理能力作为差异化卖点包装出来。路线 B 只在拿到明确的连锁品牌订单后再启动。**
