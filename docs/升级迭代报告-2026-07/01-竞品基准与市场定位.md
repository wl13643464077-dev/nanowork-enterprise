# 01 · 竞品基准与市场定位

调研时间：2026-07-26。以下均为公开信息，引用来源附在各节末尾。

---

## 一、国内餐饮 SaaS 主战场（直接竞品）

### 1.1 客如云 + 美味不用等（头部独立 SaaS）

2026 战略明确为「AI + 生态」，五大智能体已成型：

| 智能体 | 定位 | 对应纳米Work |
|---|---|---|
| 老板助手 | 经营决策数据支撑 | 老板参谋（advisor，评分 8，可比） |
| 营销助手 | 增长精准高效 | 营销活动 + 会员增长（评分 8/8，可比） |
| 超级店员 | 门店服务效率 | ❌ 无（无排班/无桌台/无点单） |
| 超级IT | 设备主动巡检、故障自动修复、连锁远程接管 | ❌ 无 |
| 智能小On | 多岗位协作减负 | 70 岗数字员工（形式相近，深度未验证） |

**关键壁垒**：
- 软硬一体收银系统 → 交易数据自然沉淀，无需商家手工录入
- 美味不用等积累 **9000 万+ 小程序用户**，抖音本地生活头部服务商资质
- 平台接入抖音、高德、美团、淘宝闪购 → 公域引流到私域运营完整链路
- 智能选址开放大数据；2026 春季推「AI+春耕计划」免费开放五大智能体（降低中小商家门槛，直接挤压新玩家的付费空间）
- 已验证客户：点都德、西塔老太太（会员规模增长至百万级）

**对纳米Work的意义**：五大智能体免费开放意味着"AI 助手"本身不再是付费理由。纳米Work若继续以"AI 员工"为核心卖点且无数据管道，将无法解释为什么要付费。

### 1.2 美团智能掌柜（平台方，最大威胁）

- **单店版**：2025 年 10 月上线，至 2026 年 3 月已有约 **70.8 万商家**使用，累计解决 **660 万个**经营困惑
- **品牌顾问（连锁版）**：2026 年 3 月 26 日发布，超 50 家连锁品牌试用
  - 帮你盯评价 / 帮你出报表 / 帮你看选址 / 帮你懂顾客
  - 品牌驾驶舱：总部定指标，一键生成所有门店报表；已有 30+ 连锁品牌生成超 **16 万份**报表，省掉约 **65%** 人工
  - 选址帮手：基于平台真实数据判断商场人气、楼层生意、周边竞品、AI 综合预测近 30 天日均到店客流（萨莉亚等在用）
- 战略表态（核心本地商业 CEO 王莆中，2026-03-13）：「帮每个商家都用上自己的 AI 助理」

**关键壁垒**：交易、评价、客流、选址数据平台独占，且免费或极低价随平台服务捆绑。

**对纳米Work的意义**：**"帮老板看数据、出报表"这条路已被美团用免费+真实数据封死。** 纳米Work的 dashboard（评分 6，数据靠手填）在这个对比下没有任何胜算，必须放弃在这个维度竞争。

### 1.3 百度智能云 Hogee + 百度一见（视觉路线）

- 定位：Hogee = 「AI 营销团队」，一见 = 「AI 数字店长」（视觉智能体）
- 数据点：中国餐饮连锁化率 2021 年 18% → 2024 年 21%，但人工巡检覆盖率不足 5%
- 实测效果：物料盘点从 30 分钟压到分钟级；某数千门店品牌服务质量核查覆盖率 5% → **95%**，满意度 98.2%；某头部连锁咖啡 **3 万家门店**全量接入，每日百万张监控图片自动审核，识别准确率 80%（人工抽检）→ **95%**
- 交互：「每天早 8 点巡检开店准备」一句指令即可定时执行并推送异常报告

**对纳米Work的意义**：证明了「定时自动执行 + 异常主动汇报」是被市场验证的产品形态。纳米Work已有 scheduler（原子认领 + 重启恢复，工程质量高）但只用于内容生成，**可以把这个能力迁移到经营巡检类场景**——这是现有资产的高价值复用点。

### 1.4 其他

- 瑞幸 AI Lucky（自研，全链路数智化 + 智萃生态圈，联合阿里云/百度智能云/华为云沉淀标准化 AI 零售方案）
- 哗啦啦、思迅美食家：传统全链路数字化 + 连锁管控

## 二、通用办公 AI 平台（间接竞品，抢的是预算）

| 平台 | 路线 | 定价 | 对纳米Work的影响 |
|---|---|---|---|
| 钉钉悟空（2026-03-17 发布） | 重构式：上千功能封装为 CLI 原子指令，AI 直接调用业务系统 | 普通会员 ¥39/月/人，高级 ¥99/月/人；算粒按需购买 | 定义了"数字员工"的定价锚点。纳米Work的积分制需要能对标解释 |
| 飞书 Aily（2026-03-19 升级） | 开放增强：常驻联系人列表的 Agent，读文档/多维表格/日程/消息，长期记忆；2026-03-28 开源飞书 CLI（11 业务域 200+ 命令 19 个 Agent Skills） | 按 AI 版本购买点数 | **纳米Work已接飞书**，可借飞书 CLI 把交付物直接落到用户日常工作流 |
| 企业微信（2026-03-30 CLI 开源） | C 端连接：唯一直连微信用户，1400 万+ 企业，日服 7.5 亿微信用户 | 生态增值服务 | **门店私域的必经入口，纳米Work完全没接，是最大的集成缺口** |

**关键判断**：门店老板做私域靠企业微信，做协作靠钉钉/飞书。纳米Work当前只接了飞书（且扫码绑群 5 个接口前端 0 调用），**企业微信零接入**——这对一个主打"会员增长 + 私域运营"的产品是致命的。

## 三、国际 AI Workforce 品类（定义纳米Work可能的差异化）

2026 年海外已形成明确品类：从"实验性聊天机器人"转向"受治理的数字劳动力"。

| 平台 | 品类 | 核心主张 |
|---|---|---|
| ServiceNow | Agentic Service Mgmt | Autonomous Workforce + AI Control Tower（Fortune 500） |
| Atomicwork | Agentic Service Mgmt | Atom 分解为专业 AI 同事，按 **8 维度治理：身份、权限、技能、预算、绩效、生命周期、治理、协作**；MCP 连 560+ 工具 |
| BotWorks（OrdoNova） | **ARP（Agentic Resource Planning）** | 「SAP 定义 ERP，Workday 定义 HCM，ARP 治理 AI 劳动力」；每个 agent 已审批、每个动作已记录、每个权限可撤销 |
| SICKR.ai | AI Workforce Governance | 不做 agent builder，做**治理层**：工作流状态、归属、审批路由、策略执行、按产出计成本、审计级历史 |
| Sema4.ai | Enterprise AI Agent | SAFE agents（Secure/Accurate/Fast/Extensible）+ Control Room |

Forrester 2026 预测：前五大 HCM 平台都将提供数字员工管理能力；从"任务型 AI"跃迁到"**角色型 AI**（role-based agents 跨系统编排完成任务）"。

**2026 选型标准**：MCP 支持、可解释审计轨迹、多智能体编排、避免厂商锁定（可换底层 LLM 不重建工作流）。

### 纳米Work已有的、恰好匹配这个品类的资产

| 品类要求 | 纳米Work现状 | 证据 |
|---|---|---|
| 每个动作已记录、审计级历史 | ✅ 已有 | `employee-outputs.js` 4 个 drill 接口可穿透到输入/产出原文/prompt 哈希/附件证据/审批边界 |
| 按产出计成本 | ✅ 已有且质量高 | `two-phase-delivery.js` 预授权→交付→结算，未交付全额退回，6 个专项测试 |
| 人在环审批 | ✅ 已有 | 风险命中进审批、内容不自动发布、`content-publish-invariants.test.mjs` 守着 |
| 身份/权限/生命周期 | ✅ 部分 | 5 种角色 + 模块级 moduleGuard + 软停用可恢复 + auth_version 即时吊销 |
| 技能治理 | 🟡 有形无实 | 409 条技能卡为纯文本，无执行能力 |
| 预算控制 | 🟡 部分 | 租户级令牌桶 20 次/分 + 全局并发 8，但无按 agent/按人的预算上限 |
| MCP 支持 | ❌ 无 | |
| 避免厂商锁定 | 🟡 部分 | 云雾 + Claude 双通道 + 模板降级，但模型名疑似别名占位 |

**这是本次审计最重要的战略发现**：项目在"AI 治理"上的工程投入（计费原子性、审批不可绕过、产出可溯源、隔离三层防护）远超其在"餐饮功能"上的投入。**它实际上更像一个 AI Workforce Governance 平台，只是穿了一件餐饮的外衣。**

## 四、UI/UX 设计基准（2026）

### 4.1 B 端后台标准已迁移

行业共识：客户每天看的不再是"十年前的灰白蓝表格系统"，而是 **Linear、Vercel、Supabase、Resend、Dub、Cal.com** 这一类产品——干净、有秩序、有细节、信息密度高但不拥挤。

- 主流技术底座：**shadcn/ui + Tailwind CSS + Radix UI + TanStack Table**（组件源码在自己仓库，可完全控制，也便于 AI 协作修改）
- Ant Design 的问题：`node_modules` 黑盒，改不了内部，默认视觉带明显"模板味"
- 视觉原则：8px 网格、至少 5 级中性灰阶、品牌色占界面面积 **不超过 10%** 且仅用于可交互元素、字号至少 4 档、色盲友好数据配色（Viridis/Wong）、避免红绿并置
- 动效纪律：位移 ≤2px、缩放 0.99、克制，不为炫技
- 标准 6 段式仪表盘蓝图：侧边导航 → 头部 → KPI 条（3-5 个）→ 图表（1-3 个）→ 数据表格 → 设置；配套暗色模式、空状态、加载骨架、错误边界

**对纳米Work的意义**：不必推翻 antd（迁移成本过高），但必须在 antd 之上建立自己的 token 层与组件层，把"antd 默认味"压掉。当前 `theme.css` 只有 16 个颜色变量，是问题根源。

### 4.2 登录页 2026 基准

主流形态：**split-screen —— 一侧极简表单，一侧 GPU 加速的动效背景或产品动态图**。

技术路线两条：
1. **CSS mesh gradient（推荐，高性能）**：多层重叠 radial-gradient，keyframes 8-15s、ease-in-out，环境化不抢注意力；Stripe/Linear/Vercel 的"高级渐变"观感，无 canvas 开销、低耗电
2. **WebGL/Shader（高冲击）**：Three.js / R3F，或 Aceternity UI 的 Premium Auth Split（左侧 raymarched torus 实时着色器）；适合把"视觉 wow"作为品牌差异化的入口页

行业提醒：「shader 背景已从 Stripe 独占变成大众商品（Framer 出 Shaders 库、Vercel v0 有 shader hero 模板）。**顶级与合格的差别只在执行质量。**」

其他要点：毛玻璃叠在动态渐变上柔化并保证文字可读性（需 0.6-0.8 透明度才有玻璃感，0.96 等于白付 blur 成本）；渐进式披露减少决策疲劳；社交/多方式登录靠前。

**对纳米Work的意义**：当前登录页用的 canvas 粒子连线是 2014-2018 年 particles.js 的标志性套路，在 2026 年是"模板站"的强信号。且连线 alpha 仅 0.18（叠加 `.nw-network{opacity:.86}` 后有效 alpha ≈0.155）压在深蓝底上几乎不可见——付了 O(n²)（1920×1080 下每帧 1431 次距离计算 + sqrt）的计算成本却没有视觉产出。

## 五、可落地的数据集成路径（若走路线 B）

调研已确认抖音生活服务 OpenAPI 是最现实的第一个真实数据源：

**接入前置**：开发者认证 → 创建生活服务应用 → 申请「到店餐饮解决方案」及接口权限 → 商家在抖音来客授权服务商应用（推荐方案二）

**可拿到的能力**：
- 门店关联及匹配（单店映射 / 总部批量映射 / 品牌门店同步）
- 团购商品创建、查询、与自有商品建立映射
- 团购核销：验券准备 `POST /goodlife/v1/fulfilment/certificate/prepare/` → 验券 `.../verify/` → 撤销 `.../cancel/` → 券状态查询 `.../get/`、批量 `.../query/`
- 对账：核销记录查询、分账查询、账单查询
- 订单查询、餐饮订座、本地生活会员体系（会员绑定/解绑同步 + 会员数据回传）

**关键字段**（验券准备返回）：`pay_amount`、`merchant_ticket_amount`、`payment_discount_amount`、`coupon_pay_amount`、`sku_id`、`groupon_type`（1 团餐券 / 2 代金券 / 3 次卡）、`market_price`、`third_sku_id`

**这些字段正是纳米Work当前完全缺失的**：真实客单、真实优惠成本、真实 SKU、真实核销时间。接一个抖音就能把 dashboard 从"手填 Excel"变成"真实数据"。

**注意**：需服务商资质 + 逐商家授权，不是纯技术工作量；美团 POS 场景需通过「商家平台子品ID」或 POS 侧 ID 关联来做双平台统一核销。
