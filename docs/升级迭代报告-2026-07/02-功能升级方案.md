## 三、P0 结构性：数据模型不是餐饮的

### 3.1 现状

74 张表（`server/src/db.js` 74 处 `CREATE TABLE`），构成：

- 支撑「AI 内容生成 + 计费 + 审批 + 溯源」：**30+ 张**
- 支撑「轻量 CRM（线索/跟进/活动）」：**9 张**
- 支撑「餐饮门店经营」：**3 张**（`orders` 单行结构、`daily_ops` 手填日报、`activities`）

用正则搜 `CREATE TABLE.*(stores?|menu|dish|sku|product|inventory|stock|shift|schedul|member|supplier|purchase|coupon|recipe|table_)`，**唯一命中是 `scheduled_runs`**（定时任务，与排班无关）。

### 3.2 缺失表清单与业务后果

| 缺失能力 | 需要的表 | 当前后果 |
|---|---|---|
| **多门店 / 连锁** | `stores` | 隔离粒度只有 `tenant_id`。开 3 家店要开 3 个账号，无法跨店对比、无法总部汇总。README 说目标用户含"区域店长"，但"区域"概念在数据模型里不存在 |
| **菜品 / SKU** | `dishes`、`skus` | `orders.product` 是**自由文本**（`seed.js:95` 塞的是 `['双人招牌套餐','午市工作餐']` 字符串）。`analysis.js:550` 的 `/products` 是 `GROUP BY o.product` —— **一个错别字就多一个"菜品"**。无法做菜单工程（明星/金牛/瘦狗/问题菜） |
| **订单明细** | `order_items` | `orders` 是单行（`lead_id, product, amount, type, region, channel`），**一单只能记一个菜一个金额**。真实餐饮是"一桌 8 个菜"。无法算客单构成、菜品搭配 |
| **成本 / 财务** | `costs`、`expenses` | `daily_ops.marketing_cost` 是唯一成本字段。无食材成本、人力、房租、水电 → **无法算毛利、无法算盈亏平衡**。而 `docs/纳米Work行业版-整合规格.md:21` 宣称驾驶舱展示「客单、毛利」 |
| **库存 / 原料** | `inventory`、`ingredients`、`stock_movements` | 无法做损耗率、备货建议。而 `employee-skills.json:3474` 有技能卡在讲「收货扫码枪解析 GS1-128 码…自动填库位与保质期」——**技能描述的能力系统完全无法承载** |
| **排班 / 工时** | `shifts`、`schedules`、`attendance` | `restaurant.json` 有 #136「需求驱动排班」员工，`docs/最终验收记录` L98 专门验收了排班派活指引。**这位员工只能输出一段文本，系统存不下排班表** |
| **会员 / 储值** | `members`、`member_cards` | `leads.stage` 有"复购"但无卡号、余额、积分、等级、消费次数。**餐饮最核心的预付储值完全缺失** |
| 桌台 / 翻台 | `tables`、`table_turns` | `Login.tsx:11` 展示「午市翻台率 2.34」，系统无法计算该指标 |
| 优惠券 / 团购券 | `coupons`、`vouchers` | 美团/抖音团购券核销无法记录 |
| 评价 / 差评归因 | `reviews` | 餐饮最重要的外部信号缺失 |
| 供应商 / 采购 | `suppliers`、`purchase_orders` | 无比价、账期、供应商评估 |

### 3.3 迁移体系形同虚设

- `scripts/migrations/` 只有 **1 个文件** `0001-baseline.mjs`（22 行），`up()` 只做存在性检查、不建表
- 真实建表在 `server/src/db.js`：`initSchema()` 74 处 CREATE + `migrateV2()` **从 L616 到 L1399 近 800 行**的单函数逐列 `ALTER TABLE ADD COLUMN`
- `0001-baseline.mjs:4` 自己写了「自 0002 起新变更应写独立迁移文件，避免继续扩大 migrateV2()」——**但没有 0002**
- `scripts/migrate.mjs:198` 是 `throw new Error('尚未实现：请填写 up() 后再运行')` 模板占位
- 无 down / 无回滚

**这是补数据表的前置障碍**：在 `migrateV2()` 里再加 8 张表会把它推到 1000+ 行，不可维护。

### 3.4 建议方案（分两阶段）

**阶段一：先建迁移基建（1 周）**

1. 写真正的 `0002-*.mjs` 起，每个变更一个文件，含 `up()` / `down()`
2. `migrateV2()` 冻结：不再新增内容，只保留历史兼容
3. `scripts/migrate.mjs` 补齐执行器（版本表、顺序执行、失败回滚、幂等）

**阶段二：按优先级补表（3-4 周）**

第一批（支撑毛利与菜品分析，价值最高）：
```
stores        门店（id, tenant_id, name, code, address, city, area, biz_type, opened_at, status）
dishes        菜品（id, tenant_id, store_id, name, code, category, price, cost, unit, status）

```
补完即可实现：真实客单价、菜品销量排行、菜单工程四象限、毛利率、盈亏平衡点 —— 这几项是老板最关心的，也是当前完全做不到的。


### 4.4 RAG 必须重构（P0，容量天花板）

**当前实现是全表暴力遍历 + JS 层余弦相似度**：

```js
// ai.js:81  全表拉候选（含 embedding TEXT，每条 20-30KB，无 LIMIT）
let docs = q.all(`SELECT id,category,title,body,callable_roles,embedding,ref_count
                  FROM kb_docs WHERE tenant_id=${T} AND enabled=1 AND category IN (...)`);
// ai.js:102  用 IN 列表拉全部 chunks（参数数量 = 文档数）
const chunkRows = q.all(`SELECT doc_id,seq,text,embedding FROM kb_chunks
                         WHERE doc_id IN (${ids.map(()=>'?').join(',')})`, ...ids);
// ai.js:105-115  JS 循环 JSON.parse + cosine
for (const c of chunkRows) { sim = cosine(qvec, JSON.parse(c.embedding)); }
```

无向量索引、无 sqlite-vec / FAISS / pgvector。且 **`node:sqlite` 是同步 API，整个检索阻塞事件循环** —— 一个大知识库的检索会冻结全服所有请求。

容量估算（1536 维 float 的 JSON 约 20-30KB/条）：

| 知识库规模 | 单次检索数据量 | 单次耗时（估） | 可用性 |
|---|---|---|---|
| 100 文档 / 300 块 | ~9 MB | 200-400 ms | 可用 |
| 500 文档 / 1500 块 | ~45 MB | 1-2 s | 勉强 |
| 1000 文档 / 3000 块 | ~90 MB | **3-5 s** | 不可用（且全服冻结） |
| 5000 文档 / 15000 块 | ~450 MB | **20 s+** | 崩溃 |

另外文档数超过 SQLite 变量上限（`SQLITE_MAX_VARIABLE_NUMBER`）会**直接报错**。

**实际可用上限约 300-500 篇文档**，而 `System.tsx:766` 向用户宣传「知识库越大越准」——工程上恰好相反。

**处置（3-5 天）**：
- 短期：加 `LIMIT` + 先用 `ref_count`/`category` 预筛候选集（如 top 200 文档）再算相似度；把检索移出主线程（worker_threads）
- 中期：引入 `sqlite-vec` 扩展（保持 SQLite 架构）或迁 PostgreSQL + pgvector
- 顺带：`rag.js:8-30` 的 `kb_citations` 表在运行时首次调用才建（注释 L9-11 承认「若调用方事务回滚会连 CREATE TABLE 一起回滚」），应直接放进 `initSchema()`
- `scripts/embed-backfill.mjs` 只有 20 行，需补进度、并发控制、断点续跑
